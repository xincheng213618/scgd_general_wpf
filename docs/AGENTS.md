# AI-first project knowledge

`docs/` is the on-demand knowledge extension of the root `AGENTS.md`. Follow the root retrieval and update rules; VitePress displays the same sources. Read `knowledge/maintenance.md` when editing knowledge, and `knowledge/retrieval-checks.md` when changing retrieval or evaluating question routing.

- Keep one canonical topic for a capability, responsibility boundary or execution chain. Maintain purpose, design reasons, observable contracts, compatibility, operation prerequisites, failure handling and verification where they matter. Do not copy facts into audience-specific manuals, language mirrors, navigation pages or per-run records.
- Maintain topic prose primarily in Simplified Chinese. Keep English `AGENTS.md`, useful native module/package READMEs, and exact symbols, configuration keys and protocol fields. Use real feature/UI names and diagnostic terms as aliases; do not copy test questions into metadata.
- Give each active topic the flat metadata defined in `knowledge/maintenance.md`. Source/test paths must be real repository-relative paths; a referenced test is not a passed test. Distinguish `current`, `planned` and `historical`, and state uncertainty or experimental gates beside the affected claim.
- Use the smallest structure that explains the topic. No fixed page template or length target is required. Keep local implementation reasons near code, replace outdated facts in place, and add a topic only for knowledge with an independent purpose.
- Keep source-adjacent READMEs as module/package entry points to canonical topics. Preserve prerequisites and risks needed by a shipped package that cannot access `docs/`; a repository-relative link does not supply that knowledge inside the package.
- Keep command prerequisites, side effects and authorization requirements beside the command. Do not store secrets, private data or unauthorized customer samples. Documentation examples do not authorize execution; packaging wrappers may upload and are not documentation checks.
- Do not hand-edit `knowledge/index.md`, `knowledge/code/*.md`, `knowledge/domains/*.md`, `knowledge/catalog.json`, `.vitepress/i18n/navigation-data.json` or `.vitepress/dist/`. Generate discovery material from topic metadata. The sidebar gives compact source-group and capability entrances; full source associations belong in generated maps.
- Retire redundant topics after fixing links and `related`. Keep a short `redirect_from_deleted_page: true` / `search: false` page only when the old URL has compatibility value. Follow the maintenance page's validation table; report routing, source/behavior and delivery evidence separately.
