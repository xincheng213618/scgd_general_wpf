# 知识检索与问答验收

本页用于验证当前检出的仓库能否帮助读者找到责任主题，并依据源码回答问题。确定性检索与源码问答分别验收：前五名命中不等于答案正确，网页构建通过也不证明产品行为。

固定查询及允许的主题 ID 保存在 `docs/knowledge/retrieval-cases.json`；产品契约由各功能主题维护。本页说明检查方法，不另存各模块的答案摘要或每轮验收记录。

## 自动检查

从仓库根目录运行：

```powershell
# 只需 Node：元数据、生成目录、固定检索与工具测试
npm run docs:check
# 另需网站依赖：包含上述检查，并构建本地网页、搜索索引和链接校验
npm run docs:build
```

这些命令不发布网站，也不启动 ColorVision。环境与文档更新流程见[维护规范](./maintenance.md)。

| 检查 | 通过条件与适用范围 |
| --- | --- |
| 知识目录 | ID 唯一、摘要和状态完整、源码/测试路径有效、相关 ID 可解析、派生目录未过期；兼容页与指令文件不混入主题 |
| 固定检索 | 每个问题的前五项至少包含一个允许主题；`include_planned` 为 true 时纳入非 current 主题，包括 planned 和 historical |
| 源码地图 | 关联来自元数据；宽泛根目录不扩散到每个子模块，只重复定位链接，不复制事实正文 |
| README 入口 | 所扫描的源码旁 README 指向存在且未退役的文档页面；不把 README 变成第二份知识目录，也不检查其正文事实 |
| 网站章节 | 已构建 HTML 中的本地页面与章节链接、生成搜索锚点有效；资源 fragment 与外链不套用 HTML 章节规则，外链不联网检查 |

文件路径存在不证明契约正确，测试路径存在不证明该测试已运行。README 扫描边界、HTML 解析和隔离测试要求统一见[维护规范](./maintenance.md)。

## 检索规则的回归边界

本地 `search` 只读 catalog 中的元数据，不读取全文或源码。网站搜索另由构建后的页面生成，不能把 CLI 排名变化解释为网站排名同步改变。

查询大小写不敏感，Windows 路径分隔符归一为 `/`。中文问句中的相邻双字片段和紧贴中文的代码符号参与检索；下划线、C++ `::` 和路径边界保持完整。排序按以下顺序比较，最后使用词法分与稳定 ID 顺序打破平局：

| 优先级 | 匹配依据 |
| --- | --- |
| 1 | 整条查询精确等于主题 ID、标题或别名 |
| 2 | 完整限定符的命中数量，其次是 ID/标题/别名明确声明的完整身份数量 |
| 3 | 所属类型或版本标签前缀回退的数量、具体程度及是否在描述中出现 |
| 4 | 非限定代码符号的完整命中数量、明确身份数量、描述命中数量 |
| 5 | 词法分，再按知识 ID 确定顺序 |

`Namespace.StateStore.Save` 可回退 `Namespace.StateStore` 或 `StateStore`，不拆成通用成员 `Save` 或外层 `Namespace`。路径可回退具体的尾部路径/文件名，不广泛匹配其中的目录名称。`widget-v1.2.3` 这类带数字版本的标签可回退元数据中的 `widget-v`；数字组件不会作为类型 owner。前缀回退不校验版本格式是否合法，也不证明所问成员存在，结果标记为 `owner-fallback`。

重复符号不叠加命中数，完整成员仍优先于 owner 回退。`score` 仅是排序的一个组成部分，消费者不能单独按它重新排序。

### CLI 数量与读取范围

```powershell
node docs/.vitepress/scripts/knowledge.mjs search "StateStore.Save" --limit 5
node docs/.vitepress/scripts/knowledge.mjs search "ONNX" --all
node docs/.vitepress/scripts/knowledge.mjs impact "UI/ColorVision.UI/PropertyEditor"
```

`search` 默认输出 12 项，`--limit N` 或 `--limit=N` 只缩小结果窗口，不改变排序；截断时显示已输出和总匹配数。N 必须是正安全整数，重复 limit 或未知选项报错，`--` 后按字面查询。默认仅 current；`--all` 纳入 planned/historical，仍排除 `search: false`。

`impact` 接收一个仓库相对路径，输出全部相交主题，不接受搜索专用选项。查询已删除路径仍有意义，不能要求目标文件当前存在。反向映射是复核候选，不是完整依赖图。

离线 CLI 回归在临时目录中只复制查询脚本与合成 catalog，从其它工作目录调用，不安装网站依赖。验证损坏正文/缺失源码不妨碍查询、查询不写回 catalog、帮助不需要 catalog，以及数量限制和状态过滤。此测试不等于所有 Node 版本上的完整首次克隆验收。

## 非限定代码符号与混合问句

`searchCatalog` 从可搜索主题的标题、别名、摘要和源码/测试路径的原始拼写识别代码形态：内部大小写边界、`HImage`/`XMLReader` 形式或 snake_case。识别后大小写无关，`StateStore`、`statestore` 和 `STATESTORE` 排序一致。`Save`、`backup`、`ID` 等普通词或缩写没有这项优先级；用户输入大写本身不是类型证据，长名称和相邻下划线也不能冒充完整符号。

代码形态并不等于类型身份，`SQLite` 这类技术名也可能满足形态。在混合问句中，若一个普通 ASCII 词在更少主题中完整命中，并且定位到不包含该代码词的竞争主题，则较广泛的代码词只参与词法分。例如 `cvsln ... SQLite` 应能找到工程文件契约。频率按当前状态过滤后的主题计一次；未知词、数字和限定 token 不参与抑制。逐个判断代码词，稀有词只出现在同一类型主题时不构成竞争。

这是目录词频启发式，新增主题可能改变排序。存在歧义时，使用完整限定名或源码路径并核对正文；`code-symbol` 标记不证明唯一责任归属或源码真实性。

### 修改检索工具时

1. 先固定尚未加入验收文件的真实问题、允许主题和原始结果。复测期间保持这些问题与 catalog 不变，分别归因算法修改和元数据补充。
2. 用隔离合成目录验证完整限定符、owner、路径、版本前缀、非限定符号、长中文噪声、大小写、名称边界、多符号去重与确定性顺序；同时覆盖未知成员、纯数字和普通词反例。
3. 检查明确身份与仅路径关联的优先级、稀有业务词与通用技术词竞争、状态/数量过滤和 CLI 匹配标记；为修复的风险增加有区别能力的回归。
4. 运行固定用例，再复测冻结的问题。保留未改善的结果，不能先照抄问句为别名再宣称通用检索改善；别名应是真实功能、界面、配置或代码名称。

纯中文问题与英文符号/中文混合问题分别抽样。问题加入固定用例后不再计作新的独立样本；工具回归通过不等于 AI 问答质量提升。

## 冷启动抽样条件

在干净克隆或新上下文中，从仓库根入口开始。不提供答案文件，不使用维护者个人记忆、以前的聊天或未提交的本地知识。代码问答不要求构建；首次构建另行记录环境、依赖和执行结果。

可用提示词：

> 只读回答下面的问题。遵守仓库 AGENTS.md，通过知识入口定位，再核对必要源码和测试。给出依据、适用范围和未验证事项。不要修改文件、运行发布脚本或操作真实设备。

## 代表性问题与语义要求

按风险类型轮换抽样，而非在本页累积每个功能的答案。下面展示选题方法，具体结论须回到对应主题和源码确认：

| 检查维度 | 示例问题 | 应核对的证据 |
| --- | --- | --- |
| 扩展契约 | 如何新增一个属性编辑器？ | 接口、发现和选择路径、生命周期、失败处理与相关测试 |
| 分层责任 | 新增算法结果叠加显示从哪里改？ | 输入来源、结果类型、注册器和实际显示入口，避免跨链套用接口 |
| 完成语义 | `RunAll` 返回 `Code=0` 就完成了吗？ | 返回值、后续事件和最终结果各自表示什么 |
| 数据持久化 | 关闭设置窗口会撤销刚才的选项吗？ | 编辑对象、提交时机、保存结果和异常分支 |
| 能力状态 | ONNX 模型现在能直接跑吗？ | 主题状态、实现入口、开关与交付条件 |
| 命令副作用 | 项目包如何只做本地构建？ | 命令实际调用链、构建与上传边界、必要前提 |

遇到未知成员、失效入口或不存在的功能前提，应明确指出，不能从相近名称补造 API。文档与源码冲突时记录差异并调查，不静默选择方便的说法。

## 记录与失败处理

每轮记录检出 commit/工作区状态、问题、使用入口、实际阅读的主题和源码、回答正确与错误之处、无关读取及未验证事项。结果留在任务报告或独立验收记录，不持续追加到产品正文；不存在固定的工具调用次数正确性门槛。

| 现象 | 处理 |
| --- | --- |
| 找不到 | 检查真实名称是否缺失、主题归属是否明确，再判断是元数据还是匹配规则问题 |
| 找错层 | 改进摘要、相关主题和责任分流，避免增加重复总览 |
| 答案过期 | 原位修正契约和源码关联，补充必要回归 |
| 能找到但无法验证 | 说明依赖、设备或样本缺口，不能编造通过结果 |
| 发现有副作用的命令 | 核对现有授权及命令附近的前提，不为只读问答执行它 |

抽样用于发现薄弱点，不是对所有模型、问题或硬件环境的认证。
