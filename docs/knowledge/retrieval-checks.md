# 知识检索与问答验收

验收对象是“当前检出的仓库能否支撑正确回答”，不是维护者已有记忆，也不是网页是否漂亮。确定性检索测试与AI问答抽样分开记录，不把关键词命中率包装成答案正确率。

## 自动检查

`retrieval-cases.json` 保存代表性问题和允许的主题ID。知识工具验证每个问题的前五个结果至少包含一个期望主题。新增别名必须有真实使用价值，不能把测试答案直接硬编码进搜索算法。

自动检查还应验证：活动页有唯一ID和摘要；源码/测试路径存在且未逃逸仓库；相关ID可解析；兼容页与 `AGENTS.md` 不混入主题；生成目录未过期；未来设计不能无状态地冒充当前能力。源码地图须按实际文件/目录派生，宽泛根目录引用不扩散到每个子模块，跨模块关联只重复链接而不复制正文。

这些检查不证明主题正文全部正确，也不证明模型真正阅读了引用。

源码旁 README 的文档入口另由零依赖检查器验证，防止仍指向缺失或退役页面；不把 README 正文收成第二份知识主题。扫描范围、支持的链接写法与不覆盖的章节检查见[维护规范](./maintenance.md)。

网站构建另校验真实 HTML 的章节定位：搜索结果和手写链接都必须指向目标页面的实际 `id`，不能只验证页面存在。回归测试使用隔离站点，覆盖中文标点、实体与百分号编码、同页/跨页链接、缺页/错锚点、代码示例排除和输出目录边界；合法的资源 fragment 与外链不套用 HTML 锚点规则。此门禁不替代正文事实核验或浏览器交互测试，也不扩大本地知识 CLI 的依赖。

## 检索规则的回归边界

改变排序规则时，先固定一组尚未录入验收文件的源码问题及允许的主题，再记录原始结果；复测期间保持问题和目录不变，分别归因算法改进与元数据补充。不能先补完整问句别名，再宣称通用检索能力改善。

工具级合成测试应覆盖：完整限定符优先于相近类型/中文泛词；限定名只回退所属类型、不将通用成员名或外层命名空间广泛匹配；较具体的owner与路径尾部、明确描述的类型优先于仅关联路径；下划线与 C++ `::` 保持识别；Windows 路径与斜杠路径一致；重复限定符不叠加得分；回退仍遵循状态过滤与确定性顺序；CLI候选输出精简且标记回退，impact保留具体映射。找到所属类型只是候选定位，不能推断未知成员存在。

纯中文问题要另测。成员识别通过不能代替能力词覆盖；如果正文已有关键契约而元数据漏掉该能力，应补充真实概念或责任边界，不为单个问法硬编码排序。固定用例与独立抽样分别报告，加入回归后的问题不再算新的独立样本。

带短模块名的混合问句还须区分“主题 ID/标题/别名精确声明该符号”与“源码/测试路径恰好含此前缀”。完整限定符命中数量相同时，明确的符号身份应优先于路径噪声；不能让 `Module.Core.Tests` 等引用淹没 `Module.Core` 自身主题。该规则不把所属类型回退提升为完整成员命中，也不证明问句中的 API 存在；整问句精确匹配、状态过滤、Windows 路径和多符号去重继续单独验证。

## 冷启动抽样条件

在干净克隆或新上下文中，从仓库根入口开始。不提供答案所在文件，不使用维护者个人记忆、以前的聊天或未提交的本地知识。代码问答不需要构建；如果要验证首次构建，必须单独记录环境、依赖和实际执行结果。

可用的提示词：

> 只读回答下面的问题。遵守仓库 AGENTS.md，通过知识入口定位，再核对必要源码和测试。给出依据、适用范围和未验证事项。不要修改文件、运行发布脚本或操作真实设备。

## 代表性问题与语义要求

| 问题 | 除定位以外必须确认的内容 |
| --- | --- |
| 如何新增一个属性编辑器？ | `IPropertyEditor` 契约、选择顺序、实例复用、失败降级与测试 |
| 属性窗口关闭后参数会恢复吗？ | 默认直接编辑、关闭不回滚、事务工作副本与宿主持久化不是同一动作 |
| 新增算法结果叠加显示从哪里改？ | 区分 Engine 历史结果 handler 与统一算法 Overlay；定位当前注册器 |
| 保存 source 会保留 TIFF 原始浮点值吗？ | 当前基准位图不是源文件字节，显示转换和编码格式影响输出 |
| `OpenImage` 返回后能立即导出完整标注吗？ | 区分调用返回、像素载入及外部渲染完成信号 |
| 历史原图删掉后结果还能显示吗？ | 原图、保存原图、保存结果图的回退与避免重复标注 |
| `RunAll` 返回 `Code=0` 就完成了吗？ | ACK 与最终结果不同；关联字段和失败条件 |
| ONNX 模型现在能直接跑吗？ | 区分未来设计与已实现能力，不凭文档存在就答支持 |
| Blob/FFT 等算法默认能使用吗？ | 核对实验功能门禁，不把有代码当作默认发布 |
| 节点结束是不是流程结束？ | 节点事件、整图结束、后处理完成三个边界 |
| 画布没保存就无界面运行，会用哪个版本？ | 区分当前 UI 画布、模板集合中的已保存数据与请求创建时的副本 |
| 项目包如何只做本地构建？ | 不把会上传的 packaging wrapper 当作普通 build |
| IntegrationDemo 也打成 cvxp 吗？ | 独立 net48 客户端与三个宿主项目包不同，不套用包上传脚本 |
| ProjectKB 独立启动就不需要 Engine 吗？ | WinExe 入口仍显式加载 Engine 并执行初始化器，不等于免依赖独立交付 |
| KB CSV 有 ColorDifference 就代表已测色差吗？ | 新行的色差/杂光列为空占位；Lv/Lc 仅切换动态键列，历史行另行核对 |
| KB 测试值等于 Recipe 上下限会失败吗？ | Enable* 门禁、包含等号的边界、百分数换算与原始/修正值的区别 |
| ColorVision.UI.Desktop 是产品主入口吗？ | WinExe 声明不等于完整启动链；该项目 App 实现为空、主窗口为空布局，产品宿主在 ColorVision |
| ImageCompute 有直方图计算 API 吗？ | 当前仅 UseCuda/Fusion 分流，不能从模块名推断任意图像算法 API |
| NativeLogBridge.IsInitialized 为 true 就开始采集了吗？ | 初始化、来源/ABI可用性与捕获开关分别判断，默认不开日志 |
| ModelViewer3D 导出是否保留当前隐藏/隔离场景？ | 界面导出重新读取源文件，不使用当前显示场景；与模型实例导出 API 区分 |
| Window3D 高度是否保留 RGB48 原始测量值？ | 先转 Bgra32，再双线性采样为 byte 灰度/alpha；可视化高度不是物理测量校准 |
| UI 测试通过能说明所有性能测量均执行了吗？ | CI 分类分进程，部分 4K/8K 探针未 opt-in 会直接返回；核对实际环境与输出 |
| 引用 ColorVision.UI 会自动加载插件吗？ | 引用包不等于调用宿主启动链；从壳层入口继续核对 PluginLoader 的条件性预检、发现和副作用 |
| 引用 ColorVision.ImageEditor 会自动加载图片吗？ | 包依赖与打开器发现、实例化、实际打开/渲染链不同，不能从包名承诺图像已载入 |
| ImageToolsModule.Register 会打开多图窗口吗？ | 只登记程序集，宿主负责装配；应在同一 ModuleCatalog 封存前注册 |
| FlowEngineAPI.RunFlow 是当前接口吗？ | 先定位 FlowEngineAPI，再核对真实 StartNode/StopNode；owner 回退不证明所问成员存在 |
| ConvertXYZ.CM_InitXYZ 返回相机句柄吗？ | 参数接收已有 IntPtr，返回 int；不能当作创建新句柄，也不能把所有 native 返回类型统一解释 |
| IsUserLoggedIn 能证明 SessionToken 仍有效吗？ | 只检查缓存结构；会话撤销、过期和用户状态由令牌登录路径另行查询 |
| RBAC 自动登录失败会清掉 LoginResult 吗？ | null 分支只清自动登录凭据，异常分支不统一清状态；不能误报本地缓存和权限已撤销 |
| RBAC 退出登录就证明会话已经撤销了吗？ | 撤销异常被吞掉后仍可清本地状态，退出界面不证明数据库撤销成功 |
| 更新检查 forceRefresh 会绕过所有缓存吗？ | 协调器进行中共享、startup 一次消费、主程序失败状态与市场旧结果回退分层核对 |
| Copilot Save 失败后 Cancel 会撤销吗？ | NotPersisted、已落盘发布失败、刷新失败、先前 Apply/后台同步分别判断 |
| Copilot Test Model 和 /doctor 一样吗？ | 真实供应商请求与本地已有健康快照不同；诊断不证明业务工具或账户额度 |
| /queue、/tasks 只是查看状态吗？ | 裸命令与控制子命令不同，确认、停止/恢复、全局位置变化和目标暂停都须核实 |
| 运行中显示的 Slash 候选都能立即执行吗？ | CanSuggest 与 CanExecute 不同；按键还受补全、multiline、follow-up 偏好与本地命令队列影响 |
| /approve 自动复核拒绝后会直接执行吗？ | 原生 Pending 与自动拒绝分支不同；一次精确重试许可仍重新复核，不能承诺执行或扩大授权 |
| Copilot 公式显示证明结果算过了吗？ | Markdown/WpfMath 是显示层，失败保留原文，不产生计算或工具执行证据 |
| 刚克隆仓库只装 .NET SDK 能编译吗？ | native helper DLL存在条件、C++工具链与运行时依赖 |
| Engine 可以删除 UI 源码只用 NuGet 构建吗？ | 六个 UI 条件包引用不覆盖 UI.Desktop 等无条件项目依赖；项目存在条件不是编译失败回退 |
| 输出目录没有 Schema 文件就是漏打包吗？ | 工程 EmbeddedResource 与编辑器先资源后磁盘的查找分开；源码目录回退成功不能证明交付程序集资源完整 |
| 刚拉取仓库只问源码，是否要先启动程序？ | 只读问答与构建、运行分别授权，不要求先完成快速上手或使用手册 |
| UI 操作都必须经过 Engine，再进入插件或项目吗？ | 从实际调用者确认；ImageEditor预览直接走自身Runner，插件装载早于启动窗口，不把目录/项目引用画成统一执行顺序 |
| 旧 ColorVisionSetup 目录还在，就是当前安装器吗？ | 历史源码与当前发布入口、外部安装工程不同；不能仅凭目录存在或仓库构建推断外部交付已验证 |
| 打开普通 PNG 是否绕过全部初始化？ | 独立打开分支仅适用特定格式；普通图像打开不能当作无副作用沙箱 |
| 主窗口缩窄后搜索框为何消失？ | 核对 MainWindow 的实际显示条件，不把布局行为误判成插件加载失败 |
| FileServer 有工厂为什么设备树看不到？ | 默认类型树过滤与工厂存在是两层，不能凭包装类虚构文件操作 |
| FlowDevice 就是本地流程引擎吗？ | 远端设备配置包装不具备本地节点图的运行和最终化契约 |
| 设备保存后远端是否已应用配置？ | 数据库更新、RC 重启请求和设备应用分别取证；void返回不证明完成 |
| 电机 Move 结束后 Position 会自动更新吗？ | 移动请求返回和位置读取不同，UI状态不能代替真实运动完成 |
| SMU 扫描失败会自动关闭输出吗？ | 核对具体失败/超时分支，不根据界面清零推断硬件关闭 |
| 只有一个物理相机时会自动绑定哪些设备？ | 核对全局SN/关联配置更新及逐项Save的持久化和重启副作用 |
| DeviceCamera 不保存文件能显示历史结果吗？ | 当前路径结果显示与待实施的设备级内存帧预览分开判断 |
| 用户登录了为什么仍不能操作？ | 粗粒度授权与局部RBAC边界，不承诺全业务统一鉴权 |
| manifest 的 requires 会阻止插件启动吗？ | 区分启动装载器、条件性 deps 检查和市场更新兼容筛选，不把声明字段当成已执行门禁 |
| 禁用插件会立即卸载程序集吗？ | 配置缓存、本次跳过与当前进程已加载程序集不是同一状态 |
| HostCopy 会复制完整插件输出吗？ | 核对触发条件、复制列表、目标目录与所缺依赖；build成功不证明宿主运行目录完整 |
| PluginExtractor 导出会完整恢复共享依赖吗？ | 区分导出和安装；共享文件恢复的路径、缺失、版本与异常处理仍须核验 |
| 数据库保存第二行失败会回滚吗？ | 浏览器逐行写入与 BatchExecuteNonQuery 是不同通道，部分成功必须查询确认 |
| 撤销能撤销数据库删除吗？ | DataTable.RejectChanges只改内存，不是已提交写入的逆操作 |
| 配置备份包含所有数据库吗？ | 设置JSON、Engine MySQL、各模块SQLite与结果文件分别归属，不存在由一份配置导出证明的全量备份 |
| SocketMessages.db 和 MsgRecords.db 是一个库吗？ | Socket与Engine MQTT消息拥有独立owner和路径，不能凭“消息日志”混同 |
| SaveConfigs 导出包含未加载的配置吗？ | 快照只来自已实例化Configs，合并的是所选目标文件；新文件不自动包含全部原始配置节 |
| Reload 会覆盖磁盘修改吗？ | 先保存再加载与ReloadFromDisk的只加载是不同入口，不能靠名字推断无写入 |
| PersistedButPublishFailed 还能直接重试吗？ | 文件已提交而回调失败，不等于未写盘；先核对持久化与内存状态，不能假设全局回滚 |
| ConfigsReloaded 订阅失败会回滚吗？ | 配置字典已替换，同步多播通知异常可中断后续订阅，旧持有者不自动重新绑定 |
| 日志等级只过滤当前窗口吗？ | 区分修改log4net Root.Level与当前显示搜索，避免通过全局输出门禁丢失后续诊断证据 |
| 关闭自动刷新后日志会补回来吗？ | 核对实时appender是否缓存未显示事件、历史读取是否另行发生，不能把暂停显示当成可靠队列 |
| LogLoadState.None 会关闭实时日志吗？ | 历史载入策略与实时appender是两个独立入口 |
| 日志窗口历史会读取全部滚动文件吗？ | 核对实际选择的appender文件、时间/大小截断及解析粒度，不把当前窗口当完整日志归档 |
| 新增模板要继承什么？ | 区分ITemplate普通参数基类、JSON直接分支与Flow/设备专用实现，不因共同基类假定同一存储契约 |
| 模板Load会清除数据库删掉的旧项吗？ | 普通实现按ID更新/追加，不清不存在的旧项；离线加载仅清保存索引，不能承诺回滚 |
| SaveIndex只包含真正修改的模板吗？ | 选择即登记索引，不是字段差异追踪；重排后索引也不是稳定记录身份 |
| 关闭模板编辑窗口会回滚吗？ | 活对象编辑、再次Load和已写数据库分别判断，不能用关窗代替撤销 |
| 模板搜索后删除会作用于哪一项？ | 核对可见索引、源集合索引与IsSelected勾选项，明确当前入口映射不一致风险 |
| SwapTemplateOrder只是改变显示顺序吗？ | 普通实现尝试改数据库ID/Pid且无统一事务，不把拖动当只读操作 |
| TrySendCommand返回true意味着脚本成功了吗？ | 方法仅提交命令，区分提交、管道、脚本退出与业务完成 |
| F5会先保存Python文件吗？ | 编辑器脏文档有保存门禁，资源树运行则直接读取磁盘；保存失败不提交 |
| 关闭终端面板会停止进程吗？ | 隐藏/停靠关闭不同于Kill/Dispose，编辑器关闭也不关闭运行会话 |
| 运行脚本工作目录是工程根目录吗？ | RunScript新会话使用脚本目录；手工终端沿用实际目录，两者不混同 |
| 在终端中打开使用的是内嵌ConPTY吗？ | 资源树入口启动外部CMD，不受内嵌TerminalService会话管理 |
| 调度暂停后相机还会继续采集吗？ | Pause 与 Interrupt/设备停止不同；TimeoutSeconds 取决于具体 Job，不是平台统一终止器 |
| 重启后一次性任务会再运行吗？ | 恢复 JSON 定义按当前时间重建触发器，不续跑原计数，也不以 SQLite 成功历史去重 |
| 调度历史筛选一个任务后，清理只删它吗？ | 清理按钮删除所有任务90天前记录，不随当前分页/任务/结果筛选收窄；失败0与无记录不同义 |
| ReadCVCIE 和 Read 都读取内嵌 XYZ 吗？ | 关联源图优先与本文件 payload 不同；路径标签、类型、尺寸和数据来源可能不一致 |
| ReadCIEFileChannel 的 Channels 为3，为什么 Data 只有一个通道？ | 保留原 header，但只读一个平面；零基索引、取消抛出及不可直接当完整多通道写回 |

## 记录与失败处理

每次抽样记录检出commit/工作区状态、问题、使用入口、实际阅读的主题和源码、正确/错误之处、工具调用或无关读取情况、未验证事项。不存在一个固定“少于几次调用就正确”的门限。

- 找不到：补充真实问题别名或主题归属，避免只增加泛泛总览。
- 找错层：改进摘要和相关主题分流，例如传统结果与统一算法平台。
- 答案过期：修正文档与源码关联，并增加适当的回归检查。
- 能找到但无法验证：明确依赖/设备/样本缺口，不编造绿色结果。
- 看到了危险命令：先检查授权边界和命令附近的副作用说明。

问答抽样用于发现薄弱点，不是穷尽所有模型、问题和硬件环境的认证。
