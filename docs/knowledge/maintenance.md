# 知识维护规范

本规范用于维护可按问题检索、与当前实现一致的 ColorVision 产品文档。读者应能通过功能名、界面名称、配置项、API 或错误信息找到对应说明；AI 使用同一正文和源码定位完成核验。任务授权与工具权限独立于文档示例。

知识应让没有聊天历史的新维护者理解目的、约束并完成验证。优先保留业务定义、设计理由、跨模块边界、兼容要求、必要操作与已知限制。局部实现原因放在代码旁；可从类型、schema 或测试可靠推导的清单优先生成，不给每个类另写网页说明。文档数量、篇幅和索引命中本身不证明接手质量。

## 单一事实位置

- 工作规则放 `AGENTS.md`，不要把所有知识塞进入口；只增加反复遇到、确实有必要的约束。
- 当前能力、契约、设计理由放权威主题。按实际源码职责与跨模块执行链组织，不按操作员、开发者、维护者分别编写手册。同一能力的操作含义、实现约束、排障和验证应在同一主题或紧密关联的独立契约中，不因受众不同复制正文。
- 主题正文以简体中文为主；`AGENTS.md` 和原生英文模块/包说明可以保持英文。取消的是重复的语言镜像，不是英文文件、代码符号或第三方原文。
- 源码旁 README 保留模块/包身份、必要前提与权威主题入口，不复制主题中的加载、配置、判定或输出契约。会随包交付的 README 不能只剩仓库相对链接：保留最小运行依赖与风险提示，说明完整知识需回到匹配版本的源码仓库读取。
- 实现细节以当前源码核对；预期契约可能暴露源码缺陷，不能以“代码就是这样”为由静默改掉契约。
- 当前主题原位维护当前事实：行为变化时替换旧说明，功能删除时清理对应入口、用法和重复解释，不逐次追加“新增、改为、已移除”的修改记录。历史细节仅在解释仍有效的兼容或迁移契约时保留；版本变化、一次性计划和本轮验证记录留在 Git/CHANGELOG 或任务报告。
- 生成目录、JSON 和网页只负责路由，不自行补事实或修改正文。`knowledge/index.md` 以源码职责提供紧凑入口，源码组地图按 `code_paths` 展开关联，`knowledge/domains/*.md` 保留能力检索；这些资料和 `catalog.json` 都由元数据生成，不手工维护。
- `docs/_history/` 专门保存不进入公开文档站点的内部历史资料。知识收集、导航、搜索、VitePress 构建和构建后页面校验都跳过该目录；不要从活动文档建立网页链接，也不要在其中维护当前行为契约。

## 清晰、不冗余的主题结构

一个主题聚焦一项能力、一个责任边界或一条完整工作链。采用类似 Microsoft Learn 的产品文档组织方式，开头直接说明用途、适用范围和当前结果，再按内容选择结构：

| 内容 | 推荐结构 |
| --- | --- |
| 概念 | 用途、工作原理、关键约束、相关主题 |
| 操作 | 前提、入口、步骤、预期结果、失败处理 |
| 参考 | 参数或接口、默认值、输入输出、限制、示例 |
| 排障 | 现象、检查顺序、判断依据、处理方式 |

源码入口和验证方法跟随所属契约；硬件、写入和外部操作的前提贴近步骤。标题应便于扫描和搜索，避免“当前最值得先看什么”一类口语标题。无需每页套齐全部章节；跨模块说明用链接连接责任边界，源码旁 README 保留随包必需信息。

维护目标是清晰、准确、可查询、不冗余，篇幅由内容需要决定，不以字数或行数减少衡量质量。合并同义段落、重复表格和多处接口说明，删除失效内容与过程记录；保留理解和使用功能所需的步骤、示例、默认值、条件、异常语义、有效兼容约束和检索词。内容较长时先改善结构，只有具有独立用途的部分才拆为主题并补齐入口，避免读者为完成一件事反复跳转。

## 元数据契约

每个活动主题在开头的 YAML frontmatter 中维护以下平面字段。字符串使用 JSON 双引号；数组写成单行 JSON 字符串数组，方便零依赖校验。已有 VitePress 字段可以保留，知识字段不能重复或写成嵌套对象。

```yaml
knowledge_id: "ui.property-grid"
knowledge_type: "topic"
status: "current"
summary: "属性编辑器的选择、实例复用、失败降级和扩展验证。"
aliases: ["自定义属性编辑器", "PropertyGrid", "IPropertyEditor"]
code_paths: ["UI/ColorVision.UI/PropertyEditor"]
test_paths: ["Test/ColorVision.UI.Tests/PropertyEditorContractTests.cs"]
related: ["ui.index"]
```

| 字段 | 维护规则 |
| --- | --- |
| `knowledge_id` | 稳定、唯一；领域前缀用于组织知识，不随标题和URL改名而随意变化 |
| `knowledge_type` | `index` 导航、`topic` 能力契约、`guide` 工作方法、`reference` 定位资料、`decision` 设计决策 |
| `status` | `current` 当前知识；`planned` 未落地设计；`historical` 仅回溯。默认查询优先当前知识 |
| `summary` | 一句话说明能解决什么问题，同时暴露重要限制；不能只写“模块介绍” |
| `aliases` | 真实能力词、界面名称、关键类型/命名空间及有辨识力的入口符号；成员限定名可通过所属类型回退，不为每个方法机械追加全名或照抄验收问题 |
| `code_paths` | 真实的仓库相对文件/目录，优先明确owner和关键入口；不填本机绝对路径、网页或虚构路径 |
| `test_paths` | 已存在且确实相关的测试/验证文件。允许空数组，空表示没有声明自动化覆盖 |
| `related` | 必要的上下游知识ID；避免把每页都连到整个知识库 |

代码路径关联是“需要复核”的线索，不是静态调用图。目录关联覆盖子路径；文件重命名时要同时改引用，符号移动时还需检查正文。路径存在只能证明定位有效，不能证明所有描述符合实现。

源码/测试文件用上述元数据和正文行内代码定位。网站只发布文档，不发布整个仓库；不要将跨出 `docs/` 的相对源码路径写成网页链接。文件在本地存在并不证明对应网页可访问。

`current` 不等于“默认启用”或“全部验证通过”。实验功能必须在摘要和正文写清门禁；未来功能必须标为 `planned`。不要手工添加永远不更新的“最后验证成功”日期。

## 随代码变化更新

先核对工作区与请求范围，再判断知识是否发生变化；无需为每次代码修改另写一段说明。

| 变更 | 知识维护范围 |
| --- | --- |
| 内部重构、局部优化，既有行为和契约保持不变 | 已有知识、实现入口与验证说明仍准确时不要求改正文；若已有说明失真，只修正受影响位置 |
| 修复缺陷，恢复已明确的契约 | 保留原契约并验证修复；已有知识、实现入口或验证说明失真时修正，不把缺陷写成新契约 |
| 公开行为、协议、默认值、架构边界、操作或构建/发布命令变化 | 更新所属权威主题中的受影响内容 |
| 源码或测试移动/删除 | 用 `impact` 检查候选并修复路径及相关正文引用，即使行为不变 |
| 新增难以从局部代码得出的设计理由、兼容约束或反复出现的陷阱 | 优先补所属主题或代码旁说明；有独立用途时才新建主题 |

已知归属时直接读取相关契约、实现和测试；归属不清才用地图或搜索。自然问句未命中时改用真实 UI 名、符号、路径或 `rg`，避免反复扩大阅读。行为或契约变化的文档归属仍不清时使用 `impact`；无候选时判断是否确实缺少上述高价值知识，不机械新建页面。

只修改知识发生变化的位置，不同步改写所有关联主题。维护后按下表验证；目录由元数据生成，不能手工编辑，也不应产生时间戳等无意义改动。

## 按变更选择验证

| 变更范围 | 本地验证与生成 | 网站验证 |
| --- | --- | --- |
| 纯代码修改，正文、元数据和引用路径均未变 | 相关代码验证；无需本地知识生成或网站构建 | 保留既有 CI 检查，不要求网站构建 |
| 仅正文措辞、说明或 AGENTS 规则 | `npm run docs:check`；标题和元数据不变时不重生成目录 | 普通正文可由文档 CI 完成全站构建；需立即验收发布页面时本地构建 |
| 主题标题、元数据、主题增删，或目录生成规则变化 | `npm run docs:knowledge` 后运行 `npm run docs:check` | 导航或路由变化时本地运行 `npm run docs:build` |
| 页面链接、章节标题、图片资源、Markdown/Vue 结构、主题样式或站点配置变化 | `npm run docs:check`，按需生成目录 | 本地运行 `npm run docs:build`；视觉/交互变化还需浏览器验证 |
| 检索、校验或生成工具变化 | 相关工具测试与 `npm run docs:check`；生成输入/规则变化时重新生成 | 影响实际网页、搜索索引或链接解析时本地运行 `npm run docs:build` |

检索规则或检索元数据变化时，复测相关固定问题及事先保留的独立问题；普通措辞调整不要求每次重新做接手试验。实际检查未运行时报告原因，不能把计划交给 CI 等同于 CI 已通过。现有文档 CI 仍执行知识检查及受影响的网站构建，本表不绕过交付检查。

```powershell
# 只读：文档归属不清或路径移动/删除时检查候选
node docs/.vitepress/scripts/knowledge.mjs impact "UI/ColorVision.UI/PropertyEditor"
# 仅目录输入变化时：写入受版本控制的派生资料；不发布
npm run docs:knowledge
# 只读校验和工具测试
npm run docs:check
# 生成本地网站并校验；不上传
npm run docs:build
```

知识目录保留主题元数据、标题与派生的定位字段，不记录文档全文哈希。未改变标题或元数据的正文修改不会改动目录；`docs:check` 不判断已构建网页是否同步。正文更新后的网站和搜索索引仍须通过 `docs:build` 重建，由上表规定的本地验证或文档 CI 完成。

`docs:check` 和本地知识 CLI 只依赖 Node，不要求网站依赖。`docs:build` 另运行 HTML 链接工具测试、构建并校验实际 HTML：生成搜索项及网页中的同页/跨页章节链接必须命中真实 `id`，中文标点和大小写不可自行改写。静态页面通过 Vue HTML 解析器读取，不执行页面脚本；代码文本、注释和惰性模板中的伪标签不能冒充目标。PDF/SVG 等本地资源只检查文件存在，不按网页章节解释其 fragment；外链不联网检查。

`docs:check` 还检查源码旁 `README.md` 指向 `docs/` 的本地页面/资源链接：目标须存在、大小写准确、解析后不逃逸文档目录，页面不能指向退役兼容页；目录链接继续检查其 Markdown 入口。README 不因此变成知识主题，不要求 frontmatter，也不进入知识目录。检查器只读取约定扫描范围内的 README，包含新建未跟踪文件，不要求 Git；跳过隐藏、依赖、构建产物等目录且不跟随目录符号链接，具体排除规则见 `docs/.vitepress/scripts/readme-links.mjs`。

README 扫描支持常用行内链接、引用式链接与简单 HTML 的 `href`/`src`，排除 frontmatter、围栏代码、行内代码和 HTML 注释；不是完整 CommonMark 渲染器。图片/PDF 等资源只检查路径，不读取为 Markdown。源码链接、外链、README 自身锚点和目标章节不由此门禁验证；页面通过不证明正文正确。修改扫描器时用隔离临时仓库验证缺页、兼容页、大小写及符号链接边界，不改坏真实仓库来制造测试。

章节检查覆盖已经发布到本地构建目录的页面，不声称验证根目录 README 的自身锚点、脚本运行后才插入的元素或浏览器点击/滚动行为。修改链接工具时用隔离临时站点注入缺页、错锚点和路径逃逸，不能把真实 `dist` 改坏来测试门禁，也不能通过忽略全部 HTML 解析错误获得绿灯。

## 授权、保密和验证分层

说明和示例不能扩大任务授权。把联网安装依赖、普通本地构建、启动应用/设备、改数据库、删除文件、签名上传分开写；危险或外部写入动作的说明贴着代码块。不要把打包上传当成普通测试命令。

不向知识正文写入账号密码、令牌、用户数据库内容、本机私有路径和未获授权的客户样本。日志和协议样例使用脱敏或合成数据。

验证分为字段/路径检查、检索路由检查、源码/行为检查、真机/交付验收。任何一层通过都不能代替其它层。完成任务时说明证据覆盖到哪一层。

## 迁移和删除

不保留没有用途的重复正文。合并时更新 `related` 和正文链接；旧网址仍有外部引用价值时保留短兼容页并禁止进入知识索引，否则可以删除。历史主题如果仍有回溯价值，应明确 `historical`，不能与当前实现混成一个搜索结果。

网站侧边栏由知识元数据和源码关联派生。不要重新添加一份手工维护的“模块—文档表”或英文镜像；需要另一种展示时，消费同一个目录。快速上手和使用手册若只是重复的阅读路线，应合并或退为展示入口；唯一的环境前提、操作风险、完成判据和故障知识必须迁入对应代码主题，不能随目录页一起丢弃。
