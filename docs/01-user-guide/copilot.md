# Copilot 使用指南

ColorVision Copilot 用来解释当前界面信息、辅助排查流程和设备问题，并在用户明确要求时协助调整模板或工作区文件。它不会自行扩大文件范围、启动流程或控制设备；固定只读机器诊断可以直接执行，受保护操作默认逐次确认，也可以由用户为下一任务或当前任务显式启用“临时自动批准”。

## 首次配置

1. 打开主界面右侧的 **Copilot** 面板。
2. 进入模型设置，选择服务商并填写 API 地址、模型和 API Key。
3. 使用连接测试确认配置可用。
4. Local MCP 仅供 Codex 等本机客户端读取 ColorVision 上下文；不使用时保持关闭。每个客户端在 `initialize` 后获得独立的进程内会话，同一台机器上的另一个客户端不能复用它创建的审批。需要让 Copilot 使用其他 MCP 服务时，在同一设置页配置 `Copilot MCP clients`。

API Key 和 MCP token 保存在本机加密配置中。发送问题前，应确认当前附加的上下文不包含不希望交给模型的数据。

## 输入区引用与访问模式

在输入框中键入 `@` 可以搜索当前 ColorVision 模板、应用菜单和解决方案文件；也可以点击左下角 `+`，选择 **关联模板、菜单或文件（@）**，在当前光标位置打开同一候选目录。继续输入会过滤候选，使用 ↑/↓ 选择，Enter 或 Tab 关联，Esc 关闭候选。关联文件会加入本轮真实附件；关联模板或菜单会加入带来源标识的结构化上下文。已保存模板开放 `InspectSavedTemplate`（本机 MCP 名称为 `get_saved_template_context`）只读工具，从已加载集合读取精确 code 和保存名称对应的有界脱敏快照；模板类型引用开放 `InspectTemplateType`（`get_template_type_context`），只返回类型身份、已加载保存名称和参数字段 Schema，不读取参数值。两者都不查询数据库、不修改或保存模板。菜单引用携带稳定菜单 ID（没有 ID 时使用完整路径），后续明确要求执行时 `ExecuteMenu` 使用该 selector，避免按显示标题再次模糊匹配；引用本身不会触发执行，执行仍遵守当前审批策略。

输入框左下角的盾牌按钮按会话选择 **按需确认** 或 **临时自动批准**：

- **按需确认** 是默认状态。受保护操作生成 Action review，用户批准后才继续同一个 Agent Session。
- **临时自动批准** 最长 15 分钟，只绑定下一任务或当前任务及启用时的工作区。当前仅适用于已预览、且执行前会逐文件复核工作区路径和 SHA-256 的工作区补丁及回滚；模板、Flow、批量转换、Shell、菜单、数据库和范围不可界定的操作仍逐次确认。切换模式不会自动批准已经在等待的操作。
- 临时授权不写入会话状态。任务结束、取消、失败、超时、工作区变化或应用重启都会恢复“按需确认”；新建会话和 `/fork`、`/branch` 创建的分支也不会继承授权。

## 数学公式

Copilot 回复支持 LaTeX 数学公式。行内公式可使用 `$...$` 或 `\\(...\\)`，独立公式可使用 `$$...$$` 或 `\\[...\\]`；跨行独立公式也会正常排版。代码片段中的美元符号不会被当作公式，无法解析的公式会保留原始文本，避免隐藏模型回复。

## Agent 工具执行

Copilot 默认使用 Microsoft Agent Framework 组织多轮推理和工具调用，不需要在模型设置中单独启用。OpenAI-compatible 与 Anthropic-compatible Profile 共用同一套工具生命周期、参数校验、超时、审计和安全策略。同一会话会保留有界的最近上下文与最初用户目标。历史窗口只接受用户和助手消息；外部调用方或旧状态中的 `system`、工具及未知角色不会进入模型。窗口截断时从完整的最近用户轮次开始，避免把缺少对应问题的孤立回答当成当前上下文；新会话不会共享这些上下文。

在“按需确认”下，创建流程、应用模板修改、通用菜单执行和切换语言等受保护操作会暂停当前 Agent Framework 会话，并在“Action review”区域显示来源、任务、工作区、影响、撤销方式、参数指纹和截止时间。点击“审查并批准”会打开独立的可滚动审批窗口；Shell 会逐字展示解析后的 Shell、工作目录、超时、完整命令、字符数和命令 SHA-256，并要求用户确认已经核对完整详情后才能批准。审查编码会把反斜杠加倍，并把换行、Tab、可能改变视觉顺序或不可见的 Unicode 控制字符显示为明确转义，命令区固定从左到右显示。关闭窗口或按 Esc 不会批准；操作在审查期间过期、取消或离开当前任务时，窗口会失效且不会执行。完整执行详情只保留在本机待审批对象中，不进入复制确认载荷、普通审计或日志，并在操作离开待审批状态后立即清除。批准后会在同一会话继续并且只执行一次；拒绝、取消或超时都不会执行该操作，模型会收到明确结果后继续回答。“临时自动批准”目前只覆盖会在执行前逐文件复核工作区路径、SHA-256 与变更集状态的工作区补丁及回滚；模板补丁、Flow 图补丁、批量图像转换、创建流程、菜单、切换语言、数据库和 Shell 仍逐次确认。内置数据库、日志、流程统计、Windows 系统信息、端口和 Shell 能力以稳定 Schema 提供给 Agent，模型结合对话自主选择零个或多个结构化调用；宿主不会按用户问题中的关键词替模型执行工具。普通概念问答可以直接回答。Windows 版本、版本号、版本类型、系统架构和 .NET 运行时优先使用固定只读检查，不需要批准；单端口状态也使用不接受命令文本的固定检查。更开放的 PowerShell/CMD 调用会绑定完整 Shell、命令和工作目录，并始终展示审批。

当前解决方案内的文件搜索、文本检索、读取文件和列目录在 Agent 模式下作为稳定只读能力提供，模型自行判断是否需要使用，普通概念问答不会因此强制搜索。搜索到候选文件后可以在同一轮继续读取，不会再出现“找到了文件但当前会话不能读”的断点。范围较广的多文件调查可由主 Agent 自主委派给全新的只读 `Explore` 子 Agent；范围较广、需要综合多个公开来源的外部资料调查可委派给只拥有网页搜索和 URL 读取能力的 `Scout`。两个互不依赖的子任务可以并行，第三个会等待可取消的并发槽。两类子 Agent 都不继承父对话、附件、任务清单、模式切换或 Skills，也不具备写文件、Shell、数据库、MCP、审批或再次委派能力；`Scout` 还完全不接收本地工作区信息。全部角色共享当前父请求的有界委派预算，结果回到主 Agent 后由主 Agent 继续回答。父调用与子运行角色、ID、停止原因和预算会保存在可展开诊断中，多次委派在主活动区仍合并为一条紧凑记录。网页搜索和网页读取仍按当前请求动态筛选：只有要求联网、提供 URL 或确实需要实时证据时才开放。简单查找直接使用网页工具，多来源调查才交给 `Scout`。直接 URL 在 `Auto` 模式下同时开放页面读取和备用网页搜索：优先读取原页面，内容不足或失败时可搜索公开网页。网页搜索会按用户给出的站点选择一个最相关结果继续读取，并沿用同源 JSON、RSS 或 Atom 的有界补读能力；深读失败时仍保留搜索结果线索，整次深读最多读取三个资源，普通页面链接不会自动爬取。使用网页证据时回答会引用工具实际返回的 URL；如果模型遗漏全部来源，运行时会在末尾补充最多三个真实来源，不会为普通问答生成来源区。成功调用会以紧凑活动行显示；没有找到结果的搜索尝试默认不占据主活动区，诊断数据仍保留在会话 trace 中。

如果模型在工具执行后没有返回任何可显示的最终回答，Copilot 会额外进行一次禁用全部工具的有界总结，只使用当前问题和已经取得的观察结果，不会再次执行操作。该总结仍为空时，本轮会明确标记为“未收到最终回答”并保留任务状态和执行记录，不会显示“任务完成”。消息卡和任务列表会提供“重试最终回答”：它跳过工具发现、Harness 循环和审批，只根据已保存对话与脱敏证据进行一次非流式生成；再次失败仍保留 checkpoint，成功后则关闭旧可执行 session，后续对话从包含新答案的可见历史建立新 session。外部 MCP 服务按行配置，格式为 `名称 | Streamable HTTP 地址 | token 环境变量 | 默认策略 | 可选工具白名单`，例如 `lab | https://mcp.example.com/mcp | LAB_MCP_TOKEN | approval | get_status=read-only,apply_patch=approval`。第五段使用远端工具的精确名称，未列出的工具不会提供给模型；留空或写 `*` 会暴露该服务发现的全部工具。远程地址必须使用 HTTPS，本机 loopback 可使用 HTTP；token 只从环境变量读取，不写入 ColorVision 配置。默认策略使用 `approval`；只对明确可信的只读工具单独设置 `read-only`。工具描述会在进程内缓存 5 分钟以减少重复发现，但每轮仍建立独立连接；外部服务若声明工具列表变更通知，当前连接会立即使缓存失效，TTL 和设置页的 `Refresh Discovery` 继续作为兜底。外部 MCP 调用的 trace 与审计只保存参数名称，不保存第三方 Schema 中含义未知的参数值。设置页诊断会紧凑显示当前 Capability Catalog 的能力数量和 revision；启用本机 MCP 后，可信客户端还可读取 `colorvision://copilot/capabilities` 获取同一份只读 JSON 目录。目录不包含远端地址、token 或参数值。某个外部服务连接失败时，本次问答继续执行，不会把连接诊断或可选搜索失败铺满聊天界面。

当只读或明确幂等的工具遇到瞬时网络错误或超时时，Agent 可以明确发起一次重试。聊天 trace 会分别显示每次尝试；同参数最多两次。非幂等操作、参数错误、拒绝和取消不会重试。如果受保护的幂等写操作需要第二次尝试，会形成新的精确调用；按需确认时重新审批，临时自动批准也会重新校验当前任务、工作区、工具声明和写入范围，不会复用上一次调用的授权记录。模型服务在尚未返回任何内容时遇到限流、临时服务故障、超时或连接中断，会进行短暂的有界重试。只要已经收到文本或工具调用，Copilot 就不会重放请求；如果此后连接中断，已经取得的输出、任务账本和工具结果会保存为“模型连接中断”状态。仍有未完成任务时可从原 Harness Session 继续；任务已完成但回答不完整时只会重试最终回答，不再调用工具。永久请求错误和用户取消不会重试。每次真实请求都会计入本轮供应商调用与 Token 预算。

未完成的 Agent 任务会随会话保存。checkpoint 同时记录当时的能力目录 revision、稳定能力指纹，以及最多 16 条、64K 字符的有界对话记忆；恢复时如果原有工具被删除，或描述、输入 Schema、风险、审批、并发、超时、审计策略发生变化，旧任务计划和历史授权会自动失效，但初始目标与最近问答仍会交给新 Session，Agent 再使用当前工具重新规划。仅新增工具不会打断已有会话。旧版本没有能力快照的 checkpoint 会安全地执行一次重新规划。checkpoint 还可保存最多 24 条经过限制和脱敏的只读 evidence artifact。写操作、失败结果和非幂等结果不会进入证据清单；普通只读工具默认只保留摘要，文档搜索、公开网页搜索和网页读取可保留最多 1600 字符的脱敏摘录，外部 MCP 的 `NamesOnly` 工具不保存返回正文。只有 session 无法恢复或必须重新规划时才注入最多 12 条历史证据，并明确要求 Agent 把它们当作不可信历史数据、重新核对易变化事实，绝不能把证据当作操作指令或历史授权。

Agent checkpoint 还维护最多 256 条结构化任务事件，用统一时间线关联运行、任务账本、工具调用、审批、运行中转向、证据制品和停止原因。事件不保存工具参数、审批正文或转向原文，只保留脱敏摘要与哈希关联键；该时间线仅用于恢复诊断和分页查询，不会作为提示重新发送给模型，也不会恢复历史写操作权限。主聊天区默认不显示这份诊断数据；启用本机 MCP 后，可信客户端可显式读取 `colorvision://copilot/task-events`，或调用只读工具 `get_agent_task_events` 按事件类型、run、工具、关联 ID 和游标查询。

多步骤请求会在回答中显示“Agent 任务”面板，包括 plan/execute 模式、完成数量、每个任务状态和本轮停止原因。未完成任务可点击“继续”从当前 Framework Session 恢复；恢复只读工作不会重复发送整段可见历史，受保护操作仍形成新的精确调用并按当前会话的访问模式处理。

工具过程采用类似 Codex 的紧凑活动行：默认只显示“读取了网页”“搜索了文件”等结果和耗时；点击单条活动才展开 Runtime、参数、资源键和错误等诊断信息。

Agent 运行时可以继续输入：按 Enter/点击 `↳` 会把要求加入当前 AgentSession，在下一次模型调用机会调整正在执行的任务；按 Tab/点击 `⇥` 会把要求排到当前任务结束后的下一轮。后续队列会显示全局顺序，并允许提前、后移、取消或移回输入框编辑；排队内容真正开始前不会写入聊天记录，开始时会读取上一轮刚完成的历史，同时沿用提交时附加的文件、活动文档和界面上下文。输入 `/btw <问题>` 则会从当前会话快照回答一次旁路问题：答案显示在输入区上方，不进入聊天记录、不影响主任务，也不会读取文件、调用工具或访问实时界面上下文；取消旁路问题同样不会停止 Agent。输入 `/resume` 会展开并聚焦现有侧栏搜索；补充会话 ID 或标题时，唯一精确匹配会直接切换，其他标题或关键词会预填搜索供用户选择，重名标题不会随机命中。Agent 正在运行时也可使用 `/resume`，源会话任务继续运行。应用正常退出时，尚未执行的后续内容会恢复为会话草稿。方形停止按钮仍表示立即取消；两种方式都不会绕过工具权限、用户意图、参数校验、文件范围或审计，临时自动批准也只覆盖当前任务中已声明的工作区补丁及回滚。完成至少一轮对话后，可输入 `/fork` 或 `/branch` 将当前聊天历史复制到一个新的会话，也可以在命令后补充新会话名称，例如 `/fork 尝试另一套标定方案`。新分支会保留已经显示的消息和当时随消息保存的附件快照，但不会带入未发送草稿、编辑区附件、Agent checkpoint 或临时授权；原会话仍保留在侧栏。分叉只作用于聊天历史，不会创建 Git 分支、复制工作目录或回滚已有文件修改。Agent 正在运行时也可执行 `/fork`：源任务不会停止，新分支会保存当时可见的回答并显示“会话分支快照”中断标记，尚未完成的模型输出、工具执行与审批状态不会在分支中继续。

同一根会话拥有分支后，聊天标题栏会显示 **会话树 · 数量**。打开后可在根会话、同级分支和嵌套分支之间直接切换；根节点排在最前，子分支跟在直接父节点之后，当前会话带勾选标记。侧栏仍把每个分支作为独立会话保留，不会折叠或合并聊天记录。旧状态中某个直接源会话已经删除时，相关分支仍会出现在树中并标记“源会话缺失”；该导航只读取持久化血缘，不传播运行状态、checkpoint 或授权。

Copilot 还会按问题类型加载随应用提供的 Agent Skill，例如流程诊断清单。技能只是一组只读工作指引和参考资料：普通问答不匹配时不会加载，也不会因此搜索文件或网页；加载技能不会获得修改模板、执行菜单或控制设备的权限。技能内部脚本当前不允许运行。

如果第三方服务端不支持其声明的 Function Calling 协议，本轮会明确失败；Copilot 不会自动切换另一套运行时重放请求，避免工具调用尤其是写操作被重复执行。模型给出的工具参数不符合 Schema 时，调用会在执行和审批之前被拒绝，并把结构化错误交回模型修正；非法的受保护调用不会弹出审批。模型偶尔生成不存在的工具名时，框架会返回 not-found 结果让模型自行纠正，同时留下紧凑、脱敏的失败记录，不会把未知函数当成真实能力执行。

## 桌面宠物联动

启用桌面宠物的“关联 Copilot”后，宠物会聚合多个 Copilot 会话的活动，而不是只跟随最后一次收到事件的会话。状态优先级为“需要输入 → 任务受阻 → 已完成待查看 → 运行中”：因此一个会话等待审批时，不会被另一个刚完成或仍在运行的会话遮住；某个排队任务被取消时，也不会把点击目标错误地切换到已取消的会话。宠物徽标在有多项活动时显示数量；单击宠物会打开当前最高优先级的会话，右键菜单中的 **Copilot 活动** 可以选择其他会话。打开“待查看”或“任务受阻”的会话后，该条未读活动会消失并自动展示下一项；暂停或等待审批的会话会保留，直到继续任务或完成审批。待确认卡仍可直接批准、拒绝或打开 Copilot 面板。这一交互采用 [Codex Pets](https://learn.chatgpt.com/docs/pets?surface=app) 的多聊天状态顺序和活动选择原则，但审批与会话数据只来自 ColorVision 自己的 `CopilotAgentTaskHost` 与 `CopilotMcpConfirmationStore`。

| 流程失败 | 流程界面右键，选择“问 AI 分析当前流程” | 流程状态、选中节点、节点参数、最近失败证据 |
| 设备异常 | 设备服务右键，选择“问 Copilot” | 在线状态、心跳、服务类型和脱敏后的配置摘要 |
| 图像分析 | 图像编辑器右键，选择“问 AI 分析当前图像” | 图像元数据、ROI 和标注摘要，不包含图像像素 |
| 模板检查 | 模板 JSON 编辑器中的 Copilot 操作 | 当前模板 JSON、校验状态和未保存状态 |
| 日志排查 | Copilot 诊断模式 | 最近日志中的相关行 |

## 流程诊断结果

流程诊断会优先给出：

1. 当前状态和重点节点。
2. 来自快照与日志的证据。
3. 按可能性排序的原因。
4. 从只读检查开始的验证步骤。
5. 有证据支持的模板字段调整候选。
6. 风险和需要人工确认的操作。

如果需要修改模板，安全顺序是“建议 -> `TemplatePatch` 差异预览 -> `ApplyTemplatePatch` 受保护调用 -> 逐次确认 -> 应用”。预览只读；未生成有效预览、未通过当前审批都不会写入模板。

在模板 JSON 编辑器处于活动状态时，也可以直接在 Copilot 中描述参数调整，例如“把 Exposure 调整到 12”。Copilot 只会先生成字段级差异预览；需要继续时，再明确要求应用对应的 `preview_id`。待确认区会说明影响，模板修改始终需要本次逐项批准。修改只进入当前编辑器，仍需由操作者决定是否保存模板。

## 安全边界

- 通用 Shell、PowerShell 和批处理命令始终绑定完整命令、Shell 和工作目录，并且必须逐次查看和批准；临时自动批准不会跳过 Shell 审批。命令运行在独立 Windows Job Object 中，根 Shell 完成、取消或超时时都会收敛其后台子进程。固定只读系统/端口诊断不接受模型命令文本。
- 不自动启动、停止或重跑流程。
- 不直接控制相机、PG、SMU、电机等设备。
- 不删除文件，也不读取工作区允许范围之外的任意路径。
- 密码、token、API Key、许可证和序列号等字段会在业务上下文中脱敏。
- AI 给出的原因属于诊断建议；执行参数调整前仍需工程师确认。

开发人员需要配置本地 MCP 时，参见 [ColorVision 本地 MCP](../02-developer-guide/core-concepts/colorvision-mcp.md)。
