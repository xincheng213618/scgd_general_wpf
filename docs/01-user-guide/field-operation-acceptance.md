# 现场操作验收清单

本页用于首次交付、版本升级和现场复测，按本次实际交付的功能确认启动、设备、流程、结果与外部系统是否符合预期。验收结论限定于记录中的版本、配置、设备和场景；一次流程成功不能证明所有场景或长期运行稳定。

先按[跨模块运行问题定位](./README.md)确定责任模块，再使用下表及对应功能文档。设备控制、通电、运动、数据库修改和远端写入须在现场授权范围内进行；只读审查只列计划与缺口，不执行这些操作。文档校验、模拟测试和既有日志不能替代本次真机验收。

## 使用方式

1. 记录主程序、项目包、插件包版本及配置位置，选择实际交付的设备、流程和输出；未交付功能标为“不适用”并说明原因。
2. 为每个选中项写明输入、预期结果和判断依据，再执行获准的最小动作。使用同一 SN、批次、请求 ID 或时间范围串起界面、日志、记录与文件。
3. 将实际结果与预期逐项比较，保存足以复核的脱敏证据。错误已经记录或能够定位失败节点，不表示该业务通过。
4. 记录未完成项、负责人及下一步；版本或配置改变后，重验受影响项。回退材料准备与实际回退演练分开记录。

| 状态 | 使用条件 |
| --- | --- |
| 通过 | 在记录的条件下执行，实际结果符合预期且有证据 |
| 失败 | 已执行，但结果或必要证据不符合预期 |
| 未测 | 尚未执行，或条件不足以作出结论；写明缺口 |
| 不适用 | 不属于本次交付范围；写明理由 |

空白项不能默认算通过。故障后的重试结果应关联原失败及处理措施，避免只保留最后一次成功。

| 配置保存 | 在获准的隔离配置上修改、保存并重启 | 重启后值仍在，相关服务状态正确；先确认编辑会话模式，关闭窗口不一定撤销改值 | [PropertyGrid 编辑与持久化](../04-api-reference/ui-components/property-grid.md) |

| 相机取图 | 连接相机，拍一张图或打开实时预览 | 图像生成并能在图像编辑器打开 | [相机服务](./devices/camera.md)、[ImageEditor](../04-api-reference/ui-components/ColorVision.ImageEditor.md) |

| 文件导出 | 导出 CSV/Excel/图片或项目结果 | 文件存在、字段顺序和客户格式正确 | [数据导出与导入](./data-management/export-import.md)、项目页 |
| Socket/MES/Modbus | 发送本项目约定的最小命令或联机样例 | 请求与最终业务结果可关联，外部系统收到预期状态码/数据；只收到受理 ACK 不算完成 | [SocketProtocol](../04-api-reference/ui-components/ColorVision.SocketProtocol.md)、[项目包总览](../04-api-reference/projects/README.md) |

## 设备验收

设备验收不要只看“列表里有”。要证明设备能被使用，并能被流程或项目包引用。

| 检查项 | 通过标准 |
| --- | --- |
| 设备资源 | 关键设备已经创建，名称和 Code 能区分现场真实设备 |
| 通信参数 | IP、端口、串口、波特率、设备号、文件路径与现场一致 |
| 最小动作 | 只执行本次获准且符合现场安全条件的动作，记录请求与实际响应；电机回零、SMU 通电、文件上传不是默认无风险检查 |
| 流程引用 | 流程节点或项目窗口能选到正确设备 |
| 日志证据 | 连接、超时、驱动、权限错误已经处理或记录 |

如果手动设备页能操作，但流程里失败，优先查流程节点绑定和模板参数；如果设备页也失败，优先查硬件、驱动、端口/IP 和服务配置。

## 流程验收

先确认本次运行使用的工作区、模板、起始节点及设备/图片/SN 绑定，说明执行的是当前画布还是已保存版本。等待该入口规定的最终状态，再核对需要的结果、图像、持久记录及导出。

共享 Flow 会话按[最终化契约](./workflow/execution.md)区分引擎结束和后处理返回；项目自有入口按项目文档判断。失败节点和日志用于定位问题，不能代替成功结果；稳定性验收还须预先定义重复次数、持续时间和可接受失败条件。

## 数据和导出验收

| 交付物 | 验收方式 | 重点 |
| --- | --- | --- |
| SQLite/MySQL | 按 SN、时间、批次查询 | 批次、模板、结果字段是否匹配 |
| CSV/Excel | 打开文件核对字段和单位 | 字段顺序、PASS/FAIL、客户旧格式兼容 |
| 图片/overlay | 打开结果图并查看标注 | 点位、框线、图层和原图坐标 |
| Socket/MES 返回 | 保存请求和响应样例 | 状态码、错误信息、`Data` 字段 |
| Summary/文本 | 核对产量、良率、失败项 | 目录、文件名、模型分组、统计口径 |

如果导出为空，不要只重试导出按钮。先确认源数据是否存在于该模块使用的数据库、内存结果或图像中，当前查看的批次和导出对象是否一致，再查项目 exporter 或字段映射。

## 外部系统验收

外部系统联调至少保留一组原始请求和响应。不同项目的协议不同，不能用一个项目的命令去验另一个项目。

| 类型 | 最小证据 |
| --- | --- |
| JSON Socket | 请求与响应 JSON、`EventName`、`MsgID` 或项目约定的关联字段、进程/模块状态 |
| 文本 Socket | 本项目约定的原始命令、终止符、返回码和数据 |
| MES/串口 | 原始报文及协议约定的帧边界（如 STX/ETX）、设备号、返回码、超时 |
| Modbus | IP、端口、寄存器地址、触发值、完成写回值 |
| 文件服务器 | 请求路径、返回文件列表、下载/上传目标路径 |

外部系统能连上但业务没跑时，先查当前进程和 handler、协议模式、输入与设备/流程前提。仅在该项目明确依赖窗口时检查窗口是否打开；支持无窗口调用的模块不应套用这一前提。区分接收、受理、完成和外部确认，按具体协议保存对应证据。
