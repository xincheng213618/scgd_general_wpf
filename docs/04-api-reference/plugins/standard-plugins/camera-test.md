# 相机生产调试

CameraTest 用于相机生产过程中的调焦、参数记录和数据存档，同时提供独立 EXE 和宿主“工具 → 相机生产调试”入口。插件 ID 仍为 CameraTest，与早期“相机出厂检测”版本保持升级连续性。启动只加载本地界面与配置，不运行 Engine 的 `IInitializer` 发现链，不主动创建 MySQL 连接、MQTT、注册中心或业务服务。ImageView 的 POI 模板在 MySQL 未连接或模板查询失败时自动使用当前用户 `ApplicationData/ColorVision/Config/ColorVision.Local.db`，无需安装 MySQL 或 SQLite；底部模板框旁提供管理、保存两个图标，可打开模板管理器或保存当前画布中的 POI，使用规则见[数据库基础契约](../../ui-components/ColorVision.Database.md)。Engine 项目引用用于复用 `StandaloneCameraSession`，该类不创建 `DeviceCamera` 或模板/结果 DAO。

本文描述当前源码能力；安装包或插件的实际功能以其版本为准。

## 输入和分析

三个入口组成两种模式：实时分析；取图/文件共用的单帧分析。支持 8/16 位灰度或彩色 BMP、PNG、JPEG、TIFF。四通道文件的 alpha 丢弃，不参与光学计算。用户在测量设置中选择 BMW、棋盘格或自动识别，再框出一个 BMW 靶标或以所需棋盘交叉点为中心的搜索区域，可添加多个区域；算法在原分辨率内定位四条边，保存固定区域 ID，失败边不删除、不填零。坐标、质量和曲线契约沿用 Core 的 BMW 与 SFR 接口。

下方矩形绘图工具与“分析 → 添加测量点”共用搜索区域：画出的矩形自动成为测量点，点击“开始分析”运行检测；移动、缩放、删除或撤销会同步区域并清除旧结果。区域身份在编辑与撤销期间保持稳定，重复名称自动分配唯一身份。旋转矩形使用其轴对齐外接范围作为搜索区域，不会旋转原图。小于 40×40 像素或越界的框保留在图中并提示修正，修正前禁止分析。加载配置会恢复可编辑矩形并清空旧绘图撤销记录。分析期间锁定绘图，避免修改中的范围混入结果。

Y 显示名对应接口 L，为解码后 `0.213R + 0.715G + 0.072B` 的相对组合信号。彩色输入计算 R/G/B/L；灰度输入只有 L。MTF50/10 和频率查询使用 cycles/pixel，Nyquist 为 0.5；编码未知保留警告。没有产品规格时不输出产品合格结论。

“色差”页通过 Core `SfrChromaticAberration` 显示 R−G、R−B、G−B 的 50% 边缘位置差，单位为输入像素。先将各通道独立居中的 ESF 恢复到同一 ROI 坐标，再在公共法线方向比较。正负号为前一通道减后一通道，方向 X/Y 表示对应原图正轴分量；导出另含轴向差、公共法线向量和对齐曲线。通道无效、缺失、方向不一致或交点不唯一时保留空值与原因，不能用零代替。色差页显示有效组数、中文原因及缺测符号；全部无效时明确提示检查通道质量。定位失败或测量框越界沿用上游原因，不误报为灰度图。该量包含整个成像链的偏移，不等于 ΔE、面积色差或纯镜头径向色差；概念可参阅 [Imatest 色差定义](https://www.imatest.com/imaging/chromatic-aberration/)，不声明实现与其数值一致。

“判定标准”可选 MTF50/10、指定频率响应下限及三组位移绝对值上限，默认全部留空。SFR 阈值作用于全部区域四边的指定通道；位移阈值独立选择通道对。结果区分未设置标准、合格、不合格和无法判定；缺测、未定位、未知编码或质量警告不能作为合格证据。只要存在确定超限项，总结为不合格，其余缺测项仍单独展示。

搜索区域与图像尺寸一起保存，换分辨率不自动缩放。最多 64 框；单帧预算 512 MiB，单区域仍服从 BMW 接口限制。结果 JSON schema 2 保留帧 ID、来源、时间、尺寸、位深、参数、目标/边状态、位移、判定标准和曲线；CSV 包含指标、位移、判定与完整 MTF 采样；保存原图输出无损 PNG，不包含显示滤镜或叠图。配置 schema 1 保持兼容，旧配置缺少判定标准时默认不检查。

当前 BMW 定位面向完整黑色对角扇区、近水平/竖直（约 ±15°）的靶标，半径至少约 55 像素。不支持任意旋转、严重透视或遮挡；较小靶标也可能因单边区域不足而返回无效。

## 相机与实时模式

相机面板提供型号、Camera ID、曝光和增益，采集参数中可选 BV_MODE/LV_MODE 和位深。Camera ID 从刷新结果选择，优先保留上次选择；`sys.cfg` 随程序提供，不要求操作员填写 SDK 路径。调用现有 cvCamera SDK，不安装驱动、不申请许可证。框架只做 RAW 成像，不执行滤轮、CIE 校正或运动。

“连接”“取图分析”“开始实时分析”和“查找相机”访问硬件；启动应用或打开图片不访问硬件。切换测量/Live 模式会先关闭旧会话。SDK 回调内复制帧，后台只保留最新等待帧；UI 同一时间只执行一次分析，丢弃停止后的过期结果。完整图像与结果属于同一次分析帧。没有 ROI 时实时模式先预览；停止并冻结后编辑区域。停止释放 Live 连接，当前图像留在界面。

“调焦趋势”保留本轮最近 300 个分析帧的标量指标，可按区域、边、通道查看指定频率 MTF 或 MTF50，显示当前值及窗口内峰值。无效测量处断开，重复帧不重复记录；这不是全部相机帧的录像。停止后保留趋势，开始新一轮、换图、换配置、修改区域或分析设置时清空，避免混合不同条件。峰值仅是调焦参考；可导出 CSV，不能据此自动断言最佳焦点。

“清晰度”页默认每条刃边一行，Y/R/G/B 横向对比，避免同一点位被四个通道重复展开。点击结果行切换刃边，点击通道数值切换当前通道，图上选中标记、曲线和大数值同步；“明细”可恢复逐通道的完整指标表。当前点的左/上/右/下四个读数固定显示在曲线上方，可直接点击切换刃边，不依赖长列表滚动。点位下拉框筛选当前范围；概览指标可选 MTF50、MTF10、指定频率 MTF 或 MTF@0.5，前两者单位为 cycles/pixel，后两者为百分数。概览、四边读数、大数值和图上标签共用显示设置；更改指标双向同步，指定频率从已有曲线按所选通道查询，不重算图像或改变记录中的分析目标频率。完整明细和导出仍使用分析时的指标口径。“定位最低值”只定位本帧、当前点位及通道筛选范围内的最低有限数值，忽略缺测；该操作不判断产品是否合格，也不判定最佳焦点。

未通过测量质量检查的通道在概览中显示“未通过”，悬停或点击可查看该边、该通道的中文原因。可用诊断数据会给出实测倾角、拟合残差、边缘跨度、信噪比或采样覆盖率，以及本帧分析时采用的限制；未计算到的诊断值不显示为零。“查看缺值”按当前点位、通道和指标筛选逐项定位，刷新帧后保持所选边与通道。有效曲线在已测范围内没有 MTF50/10 交点时仍显示空值，并说明“曲线有效但未穿过对应响应”，不误报为质量失败，也不替换为零。输入编码提示不会覆盖缺值原因；原始质量门限和导出的状态码保持不变。

Y/R/G/B 勾选同时筛选曲线、概览列和明细行，Y 对应接口 L 和明细中的 `Y (L)`。当前通道被隐藏时优先保留同一点位、同一刃边；全部取消时清空列表与曲线。没有通道数据的失败边在任一通道勾选时仍保留，显示“—”及原因，不以零代替。重新分析和视频结果刷新保持筛选；显示筛选不减少导出和存档数据。点击图上另一点位时，可退出不匹配的点位筛选并定位对应结果。色差结果表仍保留独立的位移诊断。

定位失败可通过“处理未定位”逐个跳转，所选外框以蓝色虚线标记，结果下方提供原因和操作入口。“扩大选框重试”在未找到完整靶标时提供，只对当前未旋转的矩形增加四周各 25% 的边距（宽高各增加 50%），限制在原图边界内后重新分析；原图像素范围沿用向外取整规则，不改变源图。该编辑加入绘图撤销历史，撤销/重做同步清除过期结果。它不是保证识别成功的自动修复：多个靶标应分别画框，刃边越界应调整测量框尺寸/中心距离，旋转框需手动编辑。

主工具栏保留打开、添加测量点、分析、存档与测量设置。右侧分析区默认宽 540 DIP，可通过分隔条调整。相机型号、ID、模式及位深采用同行标签和紧凑下拉框；相机面板可收起以扩大图像区域，模式和像素位数放在“采集参数”内；曝光、增益、取图和视频入口保持可见。“专注当前点”默认开启，当前点位标签只保留方向和数值，图卡、通道、指标及单位统一放在右侧当前指标下方；其他点位保留名称、中心和测量框。取消后按显示设置绘制完整标签。共享 BmwSfrOverlaySettings 的 CompactMetricLabels 默认为 false，聚合界面仅在本次渲染副本中启用，不改变控件独立复测的默认标注。输入编码和削顶风险用简短提示展示，完整原因保留在提示信息中，“检查信号”直接打开输入信号与质量设置。SFR 曲线跟随应用浅色/深色主题更新。

主界面保留聚合 SFR、色差、调焦趋势与判定页；控件的 BMW 结果窗口是独立复测入口，两者不互相替代。图像尺寸、位深、通道和文件名显示在底部状态栏，完整路径通过提示查看。“视图 → SFR 测量与显示”（或工具栏“测量设置”）集中编辑图卡类型、图像显示与四边测量框；工具栏也可直接切换 BMW、棋盘格交叉点或自动识别，两个入口同步。旧配置默认 BMW，改变图卡类型与修改框尺寸一样会清除旧结果并重新分析。棋盘格以外框中心附近的一个交叉点生成四条边，保留四侧格面；候选近似等距时提示调整外框。小框不能跨入中心或相邻交叉点的安全边界。交叉点已识别但某侧范围不足时，保留中心和其他边的结果，并提示向该侧增大外部选框；斜边角度不足仍按测量质量失败显示，不冒充定位失败。自动识别的实际类型显示在右侧当前指标与定位状态中，并写入结果 JSON。显示选项控制点位名、四边名、实际刃边拟合虚线和显示指标。指标可选 MTF50（默认）、MTF10、指定频率 MTF（默认 0.25 cycles/pixel）和 MTF@0.5；频率响应显示为百分数，MTF50/10 为 cycles/pixel。显示频率只插值查询已有曲线，不重算图像，不修改分析/判定的目标频率；默认显示数值、固定屏幕字号，缩放不会改变标签屏幕大小。生产调试和 BMW 控件使用 `BmwSfrOverlayRenderer` 共用红色矩形、四边位置、通道与数值格式。同一窗口的“四边测量框”分组使用共享 `BmwSfrRoiSettings` 设置沿刃边长度、跨刃边宽度及距靶标中心距离，单位为原图像素；各项为 0 时保持自动值。左/右框沿水平方向，上/下框沿竖直方向；距中心位置沿识别的刃边轴线确定。四边共用参数，仅在图卡类型或几何参数实际变化时清除旧结果及调焦历史并重新定位计算；仅改变标注或指标保持当前结果，取消不修改原配置；超出搜索外框保留请求坐标与无效状态，不裁切后测量。定位成功后默认显示红色中心十字，独立开关可隐藏；可选显示原图中心坐标、各 SFR 框实际宽×高、框中心到靶标中心的直线距离。中心来自识别结果，定位失败不使用外框中心代替；缩放与 DPI 只影响绘制，不改变标注的像素值。配置写入检测配置、结果 JSON 与生产存档。点击内部小矩形选择该边并联动聚合曲线及色差行；右键“斜边清晰度（SFR/MTF）”直接使用其原图范围进行独立诊断。复测窗口参数仍为该工具参数，不回写聚合记录。

相机面板直接选择现有 SDK 枚举的型号、BV_MODE/LV_MODE 和 8/16 位，Camera ID 从刷新结果选择；SDK 配置文件由程序提供，不作为操作员设置。曝光和增益在未连接时保存待应用值，连接后通过串行 SDK 命令应用，视频时也可调整；成功后清除旧等待帧并更新请求参数快照。SDK 拒绝时保留上一次已接受值并显示原因，实际范围仍由相机驱动决定。独立入口不实例化主机的 DeviceCamera 或其数据库/服务流程。

相机参数、上次 Camera ID、视频分析设置和取图保存偏好自动写入当前用户 `%APPDATA%/ColorVision/Config/CameraTest.settings.json`。关闭窗口会等待正在执行的操作及参数应用并保存最后接受的值；未连接时保留待连接使用的参数。插件和独立 EXE 共用此文件，不依赖数据库。图像特定的 POI、参考尺寸与判定仍通过检测配置或模板显式保存，不随操作偏好自动加载。读取异常时提示并使用默认值，未修改参数不覆盖异常文件；保存失败在参数提示中保留原因。

“取图后保存”默认关闭，勾选后每次取图保存无损 PNG 原始像素及同名 JSON 参数快照（来源、帧 ID、尺寸、位深、通道、采集时间、曝光、增益和取图耗时）。保存位置可选择或打开。保存先于分析，计算失败不会丢失已要求保存的原图；磁盘写入失败保留当前图像并明确显示保存失败。底部单行状态栏统一显示连接状态、采集时间、取图耗时及总计、保存状态、图像信息和视频指标；长状态文本省略显示，悬停查看完整内容。取图耗时为 SDK 等待和数据读取，总计还包含连接、显示、分析和保存；详细分析/保存耗时保留在取图耗时提示中。图像上方和相机面板不再重复展示运行状态。保存状态按当前帧更新。打开已有图像显示原文件在磁盘；手动保存原图和完整存档也更新状态。视频帧不自动写盘，停止后可通过“文件 → 保存原图”保存冻结帧。

视频分析下拉框直接选择仅预览、基础清晰度或四边 SFR，详细参数位于旁边的“设置”或“相机 → 视频分析设置”。基础清晰度复用本机视频的 `FocusAlgorithm` 与 `M_CalArtculation`，可指定 X/Y/宽/高，宽高为 0 时全幅；该值不是准确率，只适合在相同算法、曝光和区域下调焦比较。四边模式按所选图卡类型和图中测量点运行，默认同时计算基础清晰度，可关闭；无测量点时先预览并提示停止后框选。底部状态栏显示实际显示 FPS、清晰度及计算耗时；显示 FPS 包含分析/绘图开销，不冒充传感器或 SDK 回调帧率。长时间无新帧时显示等待帧，避免将旧值当成实时值。

视频使用单消费者连续处理，相机已有待处理帧时上一帧完成即开始下一帧，取消固定分析间隔。旧设置文件中的 LiveIntervalMilliseconds / AnalysisIntervalMilliseconds 会被忽略且不再写出；“分析指标”仅设置目标频率。无可用帧或串行相机操作占用时短暂让出执行；共享相机会话仍只保留最新等待帧，因此不承诺保存/计算传感器全部输出帧。此调度细节不作为界面提示。显示图像、基础清晰度和 SFR 数值来自同一帧。每帧计算不切换窗口的操作忙状态，“断开”在视频分析期间保持可用；停止、断开与关闭等待在途帧处理和参数操作，过期结果不会补画。当前不导入主机视频的十字对准、显示翻转或校正模板参数。
双击清晰度概览或明细中的结果行，或选中后按 Enter，打开该边的只读结果详情。详情同时显示原始测量框、当前通道拟合线、MTF/ESF/LSF 曲线，以及 MTF50、MTF10、当前显示频率和 Nyquist 响应；输入编码、解码指数、黑白电平、区域坐标、原图尺寸和时间来自本次分析记录。灰度输入只提供 Y 通道。展开“测量质量与计算条件”查看各通道实测值和本次质量门限；拟合后质量不通过仍保留可用拟合线，未定位则显示原搜索范围。预览只复制同帧区域的原始像素，实时采集后续帧不改变已打开的详情；切换详情通道不执行算法、不修改参数。关闭详情后主界面的分析操作保持原样。

## 生产数据存档

先在“存档信息”填写设备生产编号 / SN，可同时填写操作员、批次/工单、备注和本地存档目录。设备生产编号独立于 SDK 连接 ID，不用作目录名。“记录并存档”保存当前冻结帧；尚未框选或分析时也可保存，记录明确标记为未分析。

每条记录写入独立时间/随机 ID 目录，包含 `record.json`、无损 `image.png` 和 `profile.json`；存在同帧结果时附带 `results.json`、`metrics.csv`，有本轮调焦记录时另存 `focus.csv`。记录包含来源、尺寸、位深、时间、源像素哈希及各文件 SHA-256。文件先写入 `.pending` 目录，全部完成后改为正式目录；失败保留的 `.pending` 不算完成存档。正常关闭窗口会等待正在执行的存档完成。无需数据库。

相机采集帧保存当时请求 SDK 的型号、模式、连接 ID、位深、曝光和增益快照，后续修改配置不会改变此快照；这些参数未经过硬件回读确认。历史图片的拍摄参数未知，记录中不填入当前相机设置，时间明确为导入时间。`profile.json` 保存当前工作配置，可用于复测；它不代替原始采集参数。现阶段不提供自动跨设备对比或存档检索数据库。

## 构建与交付

插件版要求 ColorVision 1.4.15.13 或以上。发布插件使用 `Scripts\package_plugin.bat CameraTest`，上传 `.cvxp` 与插件版本索引，不生成独立 ZIP。图像控件采用宿主提供的共享程序集；简短标注开关 `CompactMetricLabels` 按运行时能力启用，宿主尚不支持时保留完整标签，不影响曲线、数值或四边选择。棋盘格需宿主同时提供新版共享 Core 的图卡类型与配套原生定位接口，插件包本身不携带这些共享组件；旧宿主的图卡入口仅显示 BMW，并在提示中说明升级要求，加载棋盘格配置时明确拒绝，不静默按 BMW 运行。

在仓库根目录 PowerShell 运行 `dotnet build .\Plugins\CameraTest\CameraTest.csproj -c Release -p:Platform=x64`。完整输出包含 `CameraTest.exe`、runtimeconfig 与托管/native 依赖；可传入一个本地图像路径自动打开。程序需要 Windows x64/.NET 10 Desktop Runtime。普通构建不复制到宿主、不上传；`.cvxp` 依赖宿主提供的共享文件，不代替独立运行包。

测试阶段使用 `pwsh -NoProfile -File .\Scripts\package_camera_test.ps1` 制作独立 ZIP，打包机需 PowerShell 7 和 .NET 10 SDK，接收端只需已配置的 .NET 10 Desktop Runtime x64 与相机驱动。脚本始终 `--self-contained false`，使用全新临时 artifacts/publish 目录，不读取旧 bin、用户配置或数据目录；不上传、不生成插件包，也不接入在线更新。版本从编译后 CameraTest DLL 的 PE FileVersion 读取并与源码清单核对，ZIP 名为 `CameraTest-<版本>-test-win-x64-<时间>.zip`，避免覆盖同版本的先前测试包。

ZIP 内只保留一个 `CameraTest.exe` 入口、已声明的托管/native DLL、Windows x64 运行资产、仓库提供的 SDK 默认配置和版权文件，另生成使用说明及逐文件 SHA-256 版本清单。不复制其他 EXE、PDB、用户配置、LIC、日志、数据库文件、图片或归档。共享 Engine 的数据库程序集可能仍在依赖中，保留程序集不代表初始化数据库。过滤后依据发布 deps.json 检查依赖完整性；不能照抄 Spectrum 的相机 DLL 排除名单。ZIP 外保留 SHA-256、打包报告和构建日志，手动分发只需 ZIP。`-OutputDirectory` 改输出目录，`-KeepBuild` 保留构建现场；如需集成已经单独验证的原生构建，可传入 `-OpenCvHelperBinary <DLL绝对路径>`，脚本将核对包内同名 DLL 与输入文件的 SHA-256，避免仍带入旧构建；默认成功后只清理本次创建且路径已核验的临时目录，失败保留现场。

## 验证范围

运行 `dotnet test .\Test\CameraTest.Tests\CameraTest.Tests.csproj -c Release -p:Platform=x64`。测试检查配置身份/边界、帧布局和内存预算、16 位显示及存档往返、文件哈希、采集参数快照与来源区分、失败边保留与 JSON 坐标，以及未连接会话不初始化 SDK。位移用例通过真实 SFR DLL 检查 8/16 位、两个方向、正反极性的已知亚像素偏移；判定与趋势用例检查缺测、绝对值阈值、窗口淘汰和重复帧。窗口用例验证离线打开图像、各页布局，以及通过绘图工具同一新增命令创建矩形后分析、修改、删除、撤销及配置恢复；可用 `CAMERATEST_SMOKE_IMAGE` 和 `CAMERATEST_SMOKE_PROFILE` 指定匹配的现场样本及配置。`CameraOperationTests` 另验证自动参数记忆、关闭时保存、异常配置保护、16 位取图保存开关与失败提示，以及连续处理可用帧、单帧处理不改变连接按钮状态、断开等待在途分析、同帧 SFR/清晰度和显示 FPS 计算。它们不操作硬件，不验证驱动/许可证、持续取流、SDK RAW 通道排列或量产重复性。BMW/SFR 算法另按其专项用例和现场样本验证；本工作区不宣称 ISO 或 Imatest 一致性。

`MeasurementDetailTests` 检查同帧约束、16 位带行填充的像素裁剪、无效通道的拟合诊断保留、主窗口详情入口和灰度通道。设置 `CAMERATEST_RESULT_IMAGES_DIR` 后，另用目录中的 `01.tif` 与 `Image_20260827102310051.bmp` 验证五个框选靶标的分析与详情数值一致性；未提供文件目录时这些现场样本测试明确跳过。可选 `CAMERATEST_RESULT_CAPTURE_DIR` 输出详情截图与原始分析 JSON，源文件哈希须保持不变；此验证不证明与 Imatest 数值相同。

打包规则用 `pwsh -NoProfile -File .\Scripts\tests\test_package_camera_test.ps1` 检查，包含相机 DLL 保留、历史数据排除、缺失依赖/文化资源和意外内置 .NET 的拒绝行为。分发前另将最终 ZIP 解压至新目录，验证启动、离线打开图像、BMW/SFR 分析与存档；仅在开发输出目录运行成功不能代替压缩包验收。
