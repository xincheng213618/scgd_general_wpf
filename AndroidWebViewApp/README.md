# ColorVision Android 运维伴侣

ColorVision Android 现场运维伴侣。已配对设备启动后直接进入现场运维，主导航只保留“运维 / 设置”。应用不再提供下载站页面或通用 WebView；安全更新与远程中继仍使用应用固定、不可编辑的服务源。

## 构建方式

1. 用 Android Studio 打开 `AndroidWebViewApp` 目录。
2. 等待 Gradle 同步完成。
3. 点击 Run 安装到手机，或执行 `Build > Build Bundle(s) / APK(s) > Build APK(s)`。

固定服务当前使用 `http://`，应用按最小明文范围配置：

- `android.permission.INTERNET`
- `android.permission.CAMERA`，仅用于扫描电脑端短时安全配对码
- `android.permission.REQUEST_INSTALL_PACKAGES`，仅在用户从设置页明确选择“下载并安装”且更新包已通过完整性、包名、版本与签名校验后交给系统安装器；启动时不会弹授权页
- `android.hardware.camera` 标记为非必需；相机用于扫描电脑端短时安全配对码
- `network_security_config.xml` 默认拒绝明文，仅允许固定域名 `xc213618.ddns.me`；应用代码进一步固定端口 `9998` 与 API 路径

现场运维通道使用电脑端短时二维码配对、HTTPS 证书固定和手机设备密钥签名。已配对手机可以读取脱敏状态、性能与告警、显示或最小化主窗口，并提交受控运维作业。固定 MQTT 恢复、ColorVision 应用重启、脱敏诊断包和单次主窗口快照由已配对手机明确确认后执行；支持会话仍需电脑端本机同意。Android 2.5 起不再调用系统指纹或锁屏凭据门禁。

Android 2.6 增加只读进程性能快照：短采样 ColorVision 的 CPU，并显示工作集、私有内存、托管堆、线程、句柄、GC 次数和主 UI 响应延迟。接口不返回进程 ID、名称、路径、命令行、主机名、用户名、网络地址、窗口内容或业务数据；单次读数只用于定位当前异常，不当作长期趋势。

Android 2.7 增加“近期远程操作记录”：手机最多读取最近 30 条去标识审计摘要，用于确认作业申请、手机批准、电脑共签、窗口控制、性能读取和证据下载等动作是否实际发生。记录不返回设备 ID、人员名称、目标 ID 或内部关联 ID，也不用于识别具体人员。

Android 2.8 增加“当前检测状态”：手机可区分流程未运行、准备中、执行中和收尾中，并显示本次用时、按历史耗时估算的进度以及最近一次完成、失败、取消或超时结果。接口只读，不返回流程名、模板 ID、批次号、节点名、参数、结果文本或检测数据；进度长期不变化也不会被单独判定为卡死。

Android 2.9 增加“持续观察”：仅在该页面位于前台时，每 10 秒读取一次聚合流程阶段、进程 CPU/工作集、主界面响应和近期告警计数；退到后台立即停止，服务器不保存采样历史。观察接口不返回日志正文或任何流程、进程、主机、用户和检测身份数据，并将同一设备的高频读取审计按 5 分钟窗口合并，避免持续写盘和淹没近期操作记录。

Android 2.10 在持续观察页面内存中保留最近 30 个聚合样本，显示 CPU 均值/峰值、工作集范围、主界面最大延迟与慢/超时次数、检测阶段切换次数以及告警计数变化，并可通过系统分享面板发送脱敏趋势。离开观察页面会立即清空这批样本，不写本地文件或服务器历史。

Android 2.11 在持续观察中增加“取消当前检测”：只有电脑端确认主工作区处于活动执行生命周期时按钮才可用。手机明确确认后，应用会创建一次性无参数取消意图并立即完成移动审批，电脑端再通过现有 `ViewFlow` 执行会话请求取消；不会选择或启动流程，不接收流程、模板、批次、节点或参数，也不要求电脑旁再次共签。请求结果进入安全作业时间线和去标识审计。

Android 2.12 增加“检测设备在线概览”：从电脑端设备注册表读取固定类别的设备总数、在线数和离线数，并接入远程排障中心与持续观察。接口不返回设备名称、编号、标识、地址、MQTT Topic、配置、原始心跳时间或测量数据，也不提供设备重连、重启或任意目标选择。

Android 2.13 将设备概览改为读取各设备实际的 MQTT 运行状态，不再依赖未可靠更新的 `IsAlive` 二元值。手机按固定类别显示就绪、忙碌、切换中、已关闭、不可用和未知计数，排障中心只把“不可用/未知”列为需要关注，避免把正常关闭的设备误报为离线；安全分享摘要也会带上同一份状态汇总。

Android 2.14 增加“消息通道健康”：单独报告 ColorVision 客户端是否已连接消息服务、已登记订阅是否全部恢复，以及最近收发活动时间。远程排障会把“Windows 消息服务进程”“ColorVision 消息通道”“检测设备状态”分成三层：通道未就绪时优先指向连接/订阅层，通道正常而设备不可用时优先指向设备进程、授权或运行状态。接口不返回地址、端口、端点、Topic、消息载荷、客户端或设备标识、配置、凭据、证书或原始日志，也不提供自动重连、重启或任意目标操作。

Android 2.15 将设备“不可用”继续拆成离线、未初始化、未授权和未归类四种固定聚合原因，并接入排障中心、持续观察和安全分享。原因只在全局汇总层展示，不按具体设备返回，也不增加设备身份、原始状态、心跳时间、地址、Topic、配置或测量数据；手机仍不执行设备初始化、授权、重连或重启。

Android 2.16 增加“重启 MQTT 消息服务”：已配对手机一次明确确认后，电脑端立即通过 ColorVisionServiceHost 的固定白名单与特权票据重启 Mosquitto，并把执行状态和有界收据写入作业时间线与审计。手机不能选择服务、命令、路径或参数；当时诊断包、主窗口快照和支持会话的电脑端本机同意不受影响。

Android 2.17 将远程取证改成单次手机确认闭环：“生成并分享诊断包”会立即创建、批准、生成、校验并打开系统分享面板；“采集并预览主窗口快照”会先显示或还原 ColorVision 主窗口，再立即创建、批准、采集、校验并进入应用内预览，不再等待电脑端共签。两类作业不接受远程参数；Web 中继发起的诊断仍需电脑端同意。诊断 ZIP 继续保持 2 MiB、脱敏和申请设备独占下载边界，主窗口 JPEG 继续保持 1.5 MiB、5 分钟和成功读取即销毁边界。

Android 2.18 将现场运维提升为应用主入口：底部导航收敛为“运维 / 下载站 / 设置”，已配对手机启动时直接使用持久化的设备密钥和证书指纹自动连接，不再被旧局域网网址连接页误判为未连接。旧“设备”和通用“主页”不再占用主导航；下载站固定为应用内置地址，不提供网址填写或选择入口。安全配对、重连与临时断线恢复只以现场运维资料为准。

Android 2.19 增加“重启 ColorVision 应用”：已配对手机一次明确确认后，电脑端只会以当前 `ColorVision.exe` 的固定内部参数启动替代进程，先持久化作业交接、再向手机返回已调度状态，旧进程随后干净退出。新进程等待旧进程结束，恢复安全运维通道并补齐成功回执；手机最多等待 90 秒并自动重连，设备密钥、证书指纹和配对资料不会因短暂断线被清除。正在执行检测或无法确认检测状态时会拒绝重启；接口不接受程序路径、命令、参数或目标进程。该能力依赖当前应用仍能响应请求，不是进程崩溃后的外部看门狗。

Android 2.20 重排移动端信息层级：运维伴侣成为首屏主体，在线状态与 ColorVision 运行摘要压缩为常驻顶部信息，常用远程操作使用双列快捷区，检测设备、服务、消息通道、取证与支持能力下沉到对应分组，不再让设备说明和重复入口挤占主要内容。已配对资料持续保留，运维页在前台时每 30 秒验证安全通道，启动和临时断线后自动重连；下载站继续只使用应用内固定地址，不提供网址填写或选择入口。

Android 2.21 增加“崩溃与卡死线索”：手机可读取最近 7 天匹配 ColorVision 的 Windows 应用崩溃、卡死、.NET 运行时失败、Windows 错误报告类别计数，以及本机转储数量和最近聚合时间，并接入远程排障建议与去标识审计。接口不接收日志源、目标程序、路径或时间范围，不返回事件正文、替换字符串、来源、文件名、路径、转储内容、进程标识、用户/机器信息、堆栈、命令行或业务数据；同一次故障可能留下多条线索，计数不等同于故障次数。

Android 2.22 增加“恢复消息通道”：已配对手机一次明确确认后，电脑端只在 ColorVision 自身 MQTT 客户端断开或已登记订阅未完全恢复时，使用当前本机配置重建连接并恢复原有订阅；通道已健康时直接返回就绪，不制造无意义断线。该动作不重启 Windows MQTT 服务，不接收地址、端口、Topic、凭据或其他参数，并接入远程排障建议、作业时间线与去标识审计。

Android 2.23 将已配对主机改为默认持续守护：离开运维页后，前台服务仍会通过固定证书和设备签名每 60 秒读取一次脱敏聚合状态；断线按 30 秒至 5 分钟退避重试，被系统回收、手机重启或应用更新后会在用户未暂停守护的前提下恢复。系统允许应用通知时，常驻通知只显示在线、检测中或需要关注等聚合状态和最近检查时间，不显示端点、主机、设备身份、告警正文、日志或业务数据；通知和持续观察页都可一键暂停，配对资料继续保留。页面内详细趋势仍只在前台每 10 秒采样并仅存内存。

Android 2.24 删除旧“局域网设备控制台”、通用网址 WebView、URL token 解析和地址粘贴入口。已配对时应用入口直接进入全屏运维伴侣，返回时不再露出一张占位小卡；未配对时只提供安全二维码配对。下载站只由应用内固定地址加载，设置页和加载失败页也只会切换到同一个固定下载站，不再保存、读取或选择下载网址，升级时会清除旧版遗留的局域网 URL 记录。后台守护不会主动弹出通知授权页；Android 仍会在系统任务管理器中标记前台服务，用户可自行在系统设置中决定是否显示通知。

Android 2.25 为当前 ColorVision 注册 Windows 原生异常恢复资格：应用连续运行达到 Windows 的恢复条件后，如果当前进程崩溃或被判定卡死，系统可向本机用户提供恢复同一个程序的机会；正常退出、系统重启和安装更新不会被强行拉起，也不接受来自手机的程序、路径、命令或参数。持续观察会显示恢复是否已登记，以及本次启动是否由 Windows 在异常退出后恢复；手机后台守护经历离线后重新连通时会明确显示“连接已恢复”。ColorVisionServiceHost 继续只监听本机命名管道，不向局域网开放特权维护接口。

Android 2.26 增加无网络入口的本机异常看门狗：只有 ColorVision 完成启动后才会激活，且只认安装目录中固定的 `ColorVision.exe`；正常退出、更新交接和单实例替换会先发出本机清理信号，不会重新拉起。进程健康运行至少 60 秒后异常消失时，看门狗才会自动恢复一次当前程序，手机后台守护随后按原配对资料重新连接。看门狗不监听端口、不接受程序路径、命令或启动参数，无法借此执行其他目标；启动握手失败时仍保留 Windows 原生异常恢复作为后备。

Android 2.27 将已配对后的应用彻底收敛为单一运维主界面：冷启动不再先创建“主页/设备”外壳，而是直接进入全屏运维伴侣；连接状态压缩为常驻一行，ColorVision 摘要收敛为两行，远程操作置顶，检测设备只作为运行状态中的紧凑入口。已配对即持续后台连接，移除页面和通知中的“暂停守护”，仅在配对被撤销或用户移除配对资料时停止。下载站地址由应用唯一常量持有，下载页直接加载固定站点，不保存、不读取、也不提供网址填写或选择；下载和设置外壳的顶部与底部导航同时缩小，为主要内容留出更多空间。

Android 2.28 在运维首屏增加六个同等大小的实时状态块：检测、设备、消息、告警、性能和应用恢复每 30 秒随安全心跳更新，异常计数直接露出，点击状态块才进入详细页。设备不再拥有独立大卡片或重复说明，状态块也不返回设备名称、地址、Topic、配置或测量数据；远程操作仍保持在实时状态之前。心跳继续复用原有脱敏 `/ops/v1/monitor`，不增加服务端采样、存储或新的权限面。

Android 2.29 增加去重的运维状态变更提醒：后台守护只在主界面无响应、严重告警、错误事件、消息通道异常、检测设备需关注或已在线主机断线时发布一条单独提醒；同一异常持续存在不会每分钟重复通知，恢复稳定后会清除旧提醒并允许下一次新异常再次触发。提醒只含固定类别与聚合状态，点击直接返回运维伴侣，不包含主机、端点、设备身份、告警正文、日志或检测数据。应用不主动弹出通知授权门禁，Android 系统通知开关仍完全由用户控制。

Android 2.30 将现有的安全取消能力提升到运维首屏：只有服务端明确返回主检测正在运行且允许取消时，“取消当前检测”才可点击；手机仍要二次确认，只提交无参数的当前主检测取消作业，不接受流程、批次、节点或检测参数。首屏总行数不增加：连接自检与取消检测并列，较低频的 MQTT 重启下沉到进一步排查，消息详情仍可直接点击实时状态的“消息”进入。

Android 2.31 让运维异常提醒直接进入对应处置：主界面无响应、严重告警、错误事件、消息通道和检测设备异常会直达有界远程排障中心，不再只回到概览；断线提醒会进入分层连接自检，配对资料仍保留并自动重试。通知只能携带应用内置的“排障”或“连接自检”目标，不接受 URL、API 路径、命令或参数；普通启动与守护常驻通知仍进入运维首屏。

Android 2.32 增加本机运维时间线：后台守护只在连接在线、连接中断、授权失效或固定异常类别确实变化时写入一条，本机最多保留 40 条、超过 7 天自动丢弃。时间线只包含时间和固定聚合类别，不保存主机、端点、设备身份、告警正文、日志或检测数据，移除配对资料时一并清除。后台服务重启后会恢复最后状态，相同异常不再因服务重启重复提醒；入口替换低频“能力目录”，不增加首屏高度。

Android 2.33 让已配对安全通道跟随 Android 系统默认网络变化：Wi-Fi、移动网络或默认路由恢复时，后台守护立即发起一次安全心跳，不再可能等待最长 5 分钟的断网退避定时。网络持续不可用时仍保留 30 秒到 5 分钟的有界指数退避，不轮询、不切换网络、不申请新权限，也不绕过原有证书固定、设备签名和配对撤销检查。

Android 2.34 在设置页把原“应用版本”一行替换为紧凑的“应用更新”入口，不增加运维首屏高度。客户端只读取应用内固定下载站的专用更新清单，只接受同源、规范命名且高于当前版本的 APK；下载时严格核对长度和 SHA-256，随后再核对应用包名、versionName、versionCode 与当前安装签名。全部通过后才打开 Android 系统安装器，不静默安装、不允许降级，也不提供网址选择。未知来源授权只会在用户明确选择下载安装后由系统按需显示，应用启动和日常运维不会出现安装权限门禁。

Android 2.35 让已配对运维伴侣在局域网直连失败时自动切换到固定下载站的设备签名中继，并在局域网恢复后自动回到完整现场通道。手机只开放“显示电脑主窗口”和“请求远程诊断”两个固定远程意图：请求继续由 Android Keystore 设备密钥签名，电脑端按原配对公钥、有效期和幂等键核验；状态摘要与执行收据再由电脑证书签名，手机按配对时固定的证书指纹验证后才展示。中继站不持有设备或电脑私钥、不接收命令文本，也不能伪造电脑在线状态或执行成功；诊断请求仍需电脑端本机同意。后台守护同步识别现场在线、远程在线和等待电脑上线，配对资料会跨网络切换持续保留。

Android 2.36 把现有的检测、设备、消息、告警、性能和应用恢复聚合状态加入电脑签名的远程快照。局域网不可用时，运维首屏仍能显示六个紧凑状态块并进入只读详情；每次刷新都重新核验电脑证书签名。固定站点只保存和转发签名 JSON，不能修改状态，也不会获得流程、模板、批次、节点、参数、结果、进程身份、主机、用户、端点、设备身份、Topic、消息载荷、配置、凭据、原始设备状态、日志正文或检测数据；远程控制能力仍只限于显示主窗口和请求本机确认的诊断。

Android 2.37 为远程运维补齐与“显示电脑主窗口”配对的“最小化电脑主窗口”。该操作不接收窗口句柄、标题、进程、命令或其他参数，手机明确确认后才提交设备签名请求；固定站点只校验白名单能力与空载荷，电脑再次核验原配对公钥、有效期和幂等键，仅操作当前 ColorVision 主窗口并返回电脑签名收据。重复请求不会重复执行，手机仍可立即使用“显示电脑主窗口”恢复窗口。

Android 2.38 把既有的“恢复消息通道”接入设备签名远程中继。手机明确确认后只能检查并恢复已配对电脑当前 ColorVision 的既有 MQTT 连接和已登记订阅；请求载荷必须为空，不能指定地址、端口、Topic、凭据、服务、命令或参数。电脑再次核验设备签名、有效期和幂等键后执行固定恢复器，健康通道保持原状，结果由电脑证书签名后返回并写入去标识审计。

Android 2.39 把既有的“取消当前检测”接入设备签名远程中继。只有电脑签名快照明确显示当前主检测仍在运行且允许取消时，手机才启用按钮；用户再次确认后提交空载荷设备签名请求。固定站点和电脑都拒绝流程、模板、批次、节点、参数、命令或其他输入，电脑只调用当前主工作区的既有取消控制器，并以幂等、去标识审计和电脑签名收据返回受理或拒绝结果。

Android 2.40 把既有的“重启 ColorVision”接入设备签名远程中继。手机只在电脑签名快照确认主检测空闲时开放按钮，明确确认后提交空载荷请求；固定站点和电脑均拒绝程序、路径、命令、参数和进程选择。电脑先返回已受理签名收据，再由固定的当前 ColorVision 重启控制器复核检测状态、启动同一路径替代进程并退出；新进程完成持久化交接后返回最终电脑签名收据，手机据此确认已经重新上线，而不是把进程退出误报为成功。

Android 2.41 把固定 Mosquitto 服务重启接入设备签名远程中继，同时不增加运维首页行数：原“恢复消息通道”入口收敛为“消息处置”，进入电脑签名消息详情后再区分恢复 ColorVision 自身连接与重启本机 MQTT 服务。MQTT 重启按钮只在签名主机仍新鲜、主检测空闲、电脑明确报告固定服务可维护且能力已发布时启用；消息连接状态不代替 Windows 服务状态。手机确认后只提交空载荷请求，不能指定服务、地址、Topic、命令、路径或参数，并允许 ColorVisionServiceHost 在最长约 90 秒执行窗口内返回已受理和最终签名回执。

Android 2.42 增加持久的“连接方式”选择，但不增加运维首页高度：可选择“现场直连优先”或“固定中继优先”，前台 30 秒心跳与后台持续守护使用同一偏好，应用和进程重启后仍然保持。首选通道临时不可用时会安全回退到另一条已配对通道，偏好不会被改写；首选恢复后自动切回。现场连接自检和移除配对资料收进连接详情，固定中继地址继续由应用内置，不能填写或选择网址。

Android 2.43 将既有的七天“崩溃与卡死线索”接入设备签名远程中继，不增加运维首页行数：入口位于电脑签名“告警”详情，只有签名主机仍新鲜且电脑明确发布只读能力时才可使用。手机无需危险操作确认，只提交空载荷请求；电脑返回的签名收据必须严格符合固定字段、布尔值、0..999 计数、七天时间窗及时间关联约束，任何缺失、多余或矛盾字段都会在显示前被拒绝。结果仍只包含固定故障类别计数和聚合时间，不返回事件正文、文件名、路径、转储内容、堆栈、进程、机器或用户身份。

Android 2.44 将一次性主窗口快照接入设备签名远程中继，入口与“崩溃线索”并列放在电脑签名“告警”详情，不增加运维首页高度。Android 12 及以上设备会为每个已配对主机另建仅允许 P-256 ECDH 的 Android Keystore 密钥，原设备签名密钥保持不变；电脑为每张快照使用一次性临时密钥，并以 ECDH、HKDF-SHA256 和 AES-256-GCM 在电脑端加密。固定站点只短时保存最多 5 分钟、仅申请设备可读取的密文，手机严格核验电脑签名收据、任务绑定、密文长度与 SHA-256、GCM 标签、JPEG 格式和最大 1280 像素尺寸后才写入唯一缓存并预览，二次点击才分享。成功落盘后手机提交签名消费确认；确认暂时失败不丢失已验证预览，站点仍按有效期清理。Android 11 及以下不使用可导出的软件私钥回退，只禁用远程快照，现有局域网 HTTPS 快照保持不变；移除配对或电脑权威撤销会同时删除独立 ECDH 密钥与远程快照缓存。

Android 2.45 在运维首页增加“当前重点”：复用后台守护的异常优先级，把主界面无响应、严重告警、消息通道、检测设备、错误事件、性能偏慢、普通警告和进行中的检测收敛成一个明确的首要事项，并直接进入对应的固定详情页。电脑离线时不会再把过期的签名快照表现为当前状态，而是标记为“上次电脑签名状态（已过期）”并优先提供远程刷新；未知计数会在进入界面前限制到固定范围，不增加远程能力、数据字段或权限。

Android 2.46 支持在一台手机上保留并切换最多六台运维电脑。每台电脑继续使用独立的 Android Keystore 签名与快照 ECDH 密钥，并分别保存证书固定、连接偏好、七天时间线和最近远程任务；后台只守护当前选中的电脑，切换时会先停止旧检查再重建客户端，避免旧请求污染新电脑状态。原有单电脑资料首次启动时自动迁移，移除或授权失效只影响对应电脑。用户可为电脑设置最多 20 个字符的本地名称，该名称不会发送给电脑或固定中继，界面也不显示主机、端点、证书指纹或设备身份。

Android 2.47 为多电脑运维补上明确的操作目标边界：运维页顶部常驻显示当前电脑的本地名称，点按即可进入管理与切换；设置页和后台守护、异常提醒通知也会显示同一名称。重启 ColorVision、重启 MQTT、恢复消息通道、取消检测、窗口最小化、诊断包、主窗口快照、作业审批和支持会话等确认框会先列出操作目标，并绑定到弹窗打开时的配对电脑；如果电脑在确认期间因人工切换或授权变化而改变，本次操作自动取消并重新连接新目标，不会把旧页面上的动作发送给另一台电脑。本地名称仍不进入请求、签名载荷、电脑端或固定中继。

Android 2.48 将连接页的电脑列表升级为本机状态总览：每台电脑分别显示最后一次后台守护得到的现场在线、远程在线、等待上线、连接中断或固定异常类别，以及距最后检查的分钟、小时或天数；授权失效和从未检查也会明确标记。状态变化时间线继续只在类别变化时追加，同时每次有界守护检查会单独更新该电脑的最后检查时间，因此稳定状态不会被误显示成很久未检查。升级前已有时间线但尚无检查时间的资料只显示“几小时前记录”，不会伪装成实时检查；非当前电脑不会新增后台轮询，状态会自然显示变旧，点按后才切换并恢复该电脑的独立守护。当前电脑授权失效但仍有可用档案时，后台服务会清空旧客户端并立即续守下一台电脑，不再让其他电脑一起失去守护。总览只读取本机既有配对档案，不增加服务端字段、网络请求、权限、身份或日志内容。

Android 2.49 在电脑总览增加用户主动触发的“巡检全部电脑（只读）”：最多六台配对电脑会以最多三台并发、每台有界短超时的方式读取既有脱敏聚合状态，并按各自保存的现场直连或固定中继偏好安全回退。巡检使用每台电脑原有的 Android Keystore 设备密钥和证书固定，结果直接按主机档案写回，不靠切换当前电脑完成，因此正常巡检前后操作目标不变，也不会启动、取消、重启、控制窗口、生成证据或提交作业；只有电脑权威返回设备授权失效时才会标记对应档案并按既有规则选择仍可用电脑。该功能只在用户打开应用明确点击后运行，不扩展后台轮询，不发送本地名称，也不增加服务端字段、权限或身份数据。

Android 2.50 将电脑总览升级为本机运维队列：连接页持续显示最近 10 分钟内各电脑检查结果的需关注、暂不可达、稳定、待巡检与授权失效计数，并按主界面无响应、严重告警、消息通道、检测设备、错误事件、连接中断、等待上线的固定顺序给出一个“处理/检查首要电脑”入口。批量只读巡检完成后同一摘要会立即留在页面，不再只依赖短暂提示；超过 10 分钟、尚未检查、时间异常或损坏的本机记录只会标记为待巡检，不会冒充当前风险。巡检本身仍不切换电脑，只有用户明确点按首要入口后才切换操作目标并重新核验该电脑；授权失效只提供移除对应本机档案的入口，不增加网络请求、后台轮询、远程动作、权限或服务端字段。

Android 2.51 在电脑总览增加“全部电脑动态”：将最多六台电脑各自在手机保存的近七天固定状态变化按时间合并，支持查看全部变化或只看主界面无响应、严重告警、消息通道、检测设备、错误事件、连接中断、等待上线与授权失效等需关注变化。页面最多渲染最近 60 条并保留真实总数，同名电脑使用本机序号消歧，当前操作目标明确标注；过期、损坏或超过一分钟的未来时间记录不会进入动态。该页面只读取既有本机档案，不触发网络、刷新、切换、远程动作或后台采集；本地电脑名称不写入状态历史、不发送给电脑或固定中继，页面也不提供包含这些名称的批量分享入口。

Android 2.52 删除下载站页面、WebView、网页相机授权和三入口导航，旧版本遗留的下载站起始标签会安全回落到运维页；签名更新与设备签名中继继续复用固定服务源，不暴露网址或浏览能力。应用接入官方 Material Design 3 Views 体系，使用 Material 3 基线 DayNight 色彩角色、排版、按钮、卡片、对话框和双入口 NavigationBar，并继续支持跟随系统、浅色与深色模式。

Android 2.67 删除与现场运维定位无关的单曲选择和 Media3/ExoPlayer 播放能力，并在升级时释放旧版本遗留的单文件读取授权。设置页同步移除不可操作的“网络权限”状态和重复的“打开现场运维”入口，只保留电脑配对、安全通道、扫码相机、主题与签名更新。

Android 2.68 移除设置页重复应用名称、配对状态和扫码动作的装饰性身份卡，改用 Material 3“电脑连接 / 权限 / 应用”分组标题与标准列表层级。每个分组末尾不再绘制多余分隔线，分组标题标记为无障碍标题；设置页继续保留六个核心条目和原有操作语义。

Android 2.69 在运维概览接入 AndroidX 标准下拉刷新，并为无法执行滑动手势的无障碍服务提供同名刷新动作：只有主概览位于前台且安全客户端可用时才会启动，若 30 秒自动心跳已在进行则复用同一次请求，不制造重复检查。刷新继续按用户保存的现场直连或固定中继优先级安全回退，结束后通过 Material Snackbar 明确区分现场直连、电脑在线、电脑仍未上线或连接不可达；进入详情、切换电脑或退到后台会立即收起刷新状态。

Android 2.70 将双通道暂不可达页改为可自动恢复的标准错误状态：停留页面时每 30 秒复用既有现场直连/固定中继心跳自动重试，恢复任一安全通道后直接回到对应运维概览；退到后台仍由原守护服务继续检查。页面只保留“立即重试、连接自检、管理连接方式”三项恢复操作，“移除当前电脑配对”下沉到连接管理页，不再与恢复主操作并列；配对资料、独立设备密钥和其他电脑档案在断线期间保持不变。

Android 2.71 将“连接方式”重构为“电脑与连接”：单电脑场景不再展示批量巡检、首要电脑、全部电脑动态和重复的当前电脑卡；只有保存两台及以上电脑时才出现电脑列表、首要处置、批量只读巡检与合并动态。页面按连接偏好、连接检查、电脑管理、安全说明和独立移除区分层，当前/首选通道压缩为两行摘要；系统返回和重复点按底部“运维”会回到运维概览，不再退出应用或停留在深层页面。移除操作仍需确认且只影响当前电脑。

Android 2.72 将“运维 / 设置”改为完整的横向页面推进与返回：使用 Material 3 标准时长和 emphasized easing，进入设置时整页从阅读方向的末端滑入，返回运维时沿原路径退出，同时自动适配 RTL；不再经过空白帧后整页闪切。页面层级、底部导航状态和系统返回语义保持不变。

Android 2.73 收紧电脑离线时的远程操作边界：首屏建议操作直接运行只读连接自检，不再先绕到连接管理页；固定中继只持有过期快照时，显示和最小化窗口等时效性控制会暂停，避免电脑稍后上线时意外执行，仍允许明确标注的只读诊断请求在固定中继等待最多 15 分钟。电脑重新上线后页面会按最新签名时间自动重建并恢复可用操作；状态文案同时区分当前能力与上次安全快照。

Android 2.74 在设置页补齐通知权限状态与恢复入口：应用仍不会在启动时主动弹出授权，只在用户明确点按“通知权限”后说明聚合运维提醒的用途并调用 Android 系统权限页；首次授权、可再次申请、永久拒绝、应用通知关闭和运维提醒渠道关闭使用不同状态与后续动作。授权成功后立即刷新后台守护通知；提醒仍不显示端点、设备身份、日志或检测数据。

Android 2.75 在设置页增加 Material 3“持续守护”开关：默认保持现有后台检查，用户关闭后立即停止前台服务与异常提醒，开机、应用更新、切换电脑和进入运维页均不会绕过该选择；前台手动连接、刷新和受控运维仍可使用。重新开启时只守护当前选中的已配对电脑，不增加网络能力、权限或数据字段。底部“设置”同步使用标准齿轮图标。

Android 2.76 完善首次配对与追加电脑流程：未配对空状态和电脑管理页均可查看电脑端配对码的准确位置、两分钟有效期与本机批准要求；扫码页在设备支持时提供补光灯。相机权限与通知权限共用经过单元测试的系统弹窗状态机，按返回键仍可再次申请，ROM 固定拒绝或不再显示授权窗时会退出黑色取景页并引导到系统设置。

Android 2.97 补全运维提醒的送达验证：提醒已经开启时，设置行会明确标注“可测试”，点按后使用标准 Material 3 对话框提供“发送测试提醒”和“系统设置”，不再无说明地跳出应用。测试通知复用正式异常提醒通道，只有运行时权限、应用通知和该通道都可用时才发送；通知不包含电脑、设备、日志或检测数据，点击后安全返回设置页。权限或通道状态在操作期间发生变化时会拒绝发送、刷新真实状态并提供修复入口，应用仍不会自动申请或修改通知权限。

Android 2.99 为运维概览增加明确的数据新鲜度：状态卡会区分正在读取、现场直连更新时间、电脑签名状态时间与过期中继摘要。连接或实时摘要读取失败时，已经加载的六项聚合状态不会突然消失，但会以错误语义明确标注“状态未更新”并展示上次成功时间；当前页面尚无成功摘要时则将状态转为不可用，不再停留在“读取中”。手动刷新反馈同步区分连接不可达和连接已成功但实时摘要缺失，避免把旧的设备、消息、告警或性能摘要误认为当前实时状态。

Android 3.00 将远程排障中心调整为异常优先的信息层级：有发现项时，首屏会直接展示最高价值的脱敏证据、最近时间和安全动作，再列出近期事件、作业、消息与设备概览；不再用两张连续状态卡和一段健康指标把真正的异常推到页面下方。顶部状态会明确显示待复核项数，正常状态则直接从运行概览开始；刷新失败会恢复错误详情，并将仍保留的旧报告明确标注为“上次成功摘要、仅供参考”，所有动作的只读、确认和电脑共签边界保持不变。

Android 3.01 修正“电脑与连接”页面把上次设备巡检状态误当成当前连接的表达：进入页面会按用户首选顺序实际确认现场直连和固定中继，确认期间不再沿用上一页通道；成功后明确显示当前安全通道，中继可达但电脑未上线时单独说明，两种通道都不可达时则保留配对资料并将连接自检提升为首要动作。连接偏好、电脑管理与移除边界保持不变，授权撤销仍会立即停止回退并进入安全失效处理。

Android 3.02 完善运维提醒的权限恢复路径：系统把通知权限标记为不再弹出后，设置页会立即显示“需在系统设置开启”，不再把已经被系统阻止的状态写成“尚未开启”；用户再次点按“运维提醒”会直接进入系统通知设置，不再重复解释和发起一个不会出现的权限弹窗。首次开启说明的主动作也改为明确的“允许提醒”，拒绝结果会在当前页给出可恢复反馈；提醒测试、持续守护开关和隐私边界保持不变。

Android 2.4 支持一次性主窗口安全快照：电脑端只渲染 ColorVision 主窗口并压缩为不超过 1.5 MiB 的 JPEG，不捕获整个桌面；快照仅保留 5 分钟，只能由申请设备读取一次，成功读取后立即从电脑端删除。手机先在应用内预览，只有用户再次点击分享才会把缓存副本交给其他应用。

“连接自检”会依次检查手机网络、主机解析、TCP 安全端口、TLS 证书固定、设备签名和电脑时间，并只展示不含密钥、证书指纹、设备 ID、用户名或机器名的调试摘要。临时断线不会要求用户删除配对资料。

“近期日志摘要”只读取固定大小的最新日志尾部，返回分级计数、来源分类和最多 12 条脱敏异常事件；不会返回日志文件名、路径或完整原始日志。手机可以通过系统分享面板转发同一份安全诊断摘要。

“远程排障中心”把脱敏事件、主窗口状态和待处理作业汇总成固定建议。Android 端只识别内置白名单动作：查看脱敏事件、显示主窗口、查看审批，以及确认重启 MQTT；未知动作不会显示。MQTT 重启由已配对手机一次明确确认后执行，只能通过 ServiceHost 操作固定 Mosquitto 服务，不接受服务名、命令或路径等远程下发参数。

“白名单服务健康”只显示 ColorVision 后台服务与 MQTT 消息服务的规范化运行状态，不返回服务账户、程序路径或启动参数。排障中心只有在 Windows 服务管理器确认本机 MQTT 已停止或暂停时才建议维护；旧日志本身不会触发重启建议。

“作业与审批”使用面向手机的安全摘要：显示固定目标、风险、四阶段时间线和证据类型，不返回申请设备、理由、输入参数或电脑端内部收据 ID。安全分享摘要会附带同一份白名单服务状态。

手机明确确认后，电脑端会立即生成诊断 ZIP，发起作业的手机可在 24 小时内下载并分享。包内仅包含白名单运行状态、脱敏事件、规范化服务健康和去标识审计；不包含机器名、用户名、设备 ID、进程 ID、网络地址、凭据、原始日志、数据库、用户文档或图像。下载固定为 2 MiB 上限，响应与本机文件都会核对 SHA-256，其他已配对设备无法读取。

“引导支持会话”是最长 15 分钟的有限文本通道：会话只对发起它的已配对设备可见，必须先由电脑端本机同意，且只在激活且未过期时允许手机或 Web 中继交换消息。手机在等待本机同意时每 5 秒刷新，进入可输入状态后停止重建页面；单条现场消息最多 500 字。接口不会返回设备 ID、电脑账户、内部任务或审计标识，也不支持远程桌面、命令或任意文件。
