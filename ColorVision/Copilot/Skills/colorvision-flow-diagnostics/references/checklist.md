# Cross-layer diagnostic checklist

Choose the evidence source before diagnosing. The current UI and uncorrelated logs are clues; recorded incident selection metadata identifies a record but does not mean its evidence has been read. Use exact returned IDs and retrieve only the evidence needed for the question.

| Need | Tool and evidence chain | Interpretation boundary |
| --- | --- | --- |
| Find a retained run, including a slow or normal run without an incident | `ListFlowRuns` / `list_flow_runs`; use a complete known `flow_key` only when available, otherwise omit it. Follow the returned `run_record_id`. | Optional FlowKey matching is full, Unicode-trimmed and case-sensitive; do not substitute a name, prefix, truncated/redacted label, or template ID. Omitting the filter includes legacy and unknown records. ID-descending pages are not execution-start order. |
| Find or inspect an incident | `ListFlowIncidents` / `list_flow_incidents` when no exact incident ID is known, then `InspectFlowIncident` / `inspect_flow_incident` with the returned `incident_id`. | Follow the detail's associated `run_record_id` and attempt identifiers. An incident ID is not a run ID; an empty incident list does not prove a successful run. |
| Read execution events | `InspectFlowRunEvents` / `inspect_flow_run_events` with an exact run ID from discovery, incident detail, read history, or the user. Use it when incident events are truncated or earlier events are needed. | The first window is latest; continue toward older windows using the returned cursor unchanged. Each page is sequence/ID ascending. Reaching the oldest retained event does not prove every event was persisted. |
| Read detailed node attempts | `InspectFlowRunAttempts` / `inspect_flow_run_attempts` with the exact run ID; optionally use an exact recorded node ID unchanged, without a GUID assumption. Match an event or incident's `attempt_id` to returned rows and continue toward older attempt IDs when needed. | Each latest-ID window is delivered ID ascending. Preserve repeated attempt numbers as distinct attempt IDs. Read outcome recognition and text coverage; an attempt failure does not prove that the run stopped, and attempt records do not establish `ContinueOnFail`, parameters, or the executed canvas. |
| Compare prior states, durations, or exact-node attempts | `InspectFlowRunHistory` / `inspect_flow_run_history` with the exact run ID; use only an exact recorded `node_id` when needed. | Read the delivered window and coverage. Legacy identity is a weaker reference; bounded success samples are not a population success rate or customer PASS/FAIL. |
| Inspect retained configuration structure | `InspectRecordedFlowTemplate` / `inspect_recorded_flow_template` with the exact run ID. | Only saved node identities, property names and verifiable connections are returned, not parameter values. Missing layout and omitted nodes limit the evidence. Retained bytes may omit unsaved canvas changes. |
| Compare retained configurations | Select explicit baseline/current run IDs from run discovery, read history, or the user, then `CompareRecordedFlowTemplates` / `compare_recorded_flow_templates`. | Keep the two IDs and their order fixed while paging. Counts and delivered details differ; finishing rows does not make bounded field-name lists complete. Saved differences do not prove executed configuration or fault causality. |
| Inspect the current canvas | `InspectFlowGraph` / `get_flow_graph`; request parameter summaries explicitly only when needed. | Current revision, saved template version and recorded hash are different evidence. A current graph or valid-format hash does not establish the historical execution canvas. |

For paged tools, inspect `coverage`, `has_more` and `next_cursor`; continue only as needed, preserving each tool's query bindings. Cursor failure requires a fresh query, not invented or edited cursors. Recorded-data pages read live retained data rather than freezing all history. Missing storage/schema, unavailable evidence and a successful empty page are different results. Do not replace a failed formal read with guessed IDs, direct SQL, or raw payload inspection.

- Flow: running/failed/ignored state, current node, elapsed time, timeout, `ContinueOnFail`.
- Device: use `InspectDeviceServices` / `inspect_device_services` on demand for already-loaded metadata and supported built-in cached state. Discover the directory first; focus only with the returned `device_ref` and `source_instance_id` passed as `expected_source_instance_id`, without a cursor or name/code fallback. Follow directory pages only as needed. Preserve explicit unsupported/read-failed/unknown states; cached status and its observation time do not prove online health, heartbeat freshness, readiness, or command completion. This tool does not read configuration, probe, connect, or control devices.
- Data: input artifact exists, output schema matches, parser returned a usable result.
- Downstream: failure was propagated, ignored deliberately, or converted into an empty/default result.
- Evidence: report the source, exact incident/run/attempt/node identifiers, timestamps and coverage actually delivered; distinguish observation from inference and retain unknown outcomes. Redact credentials and tokens; do not request SNs, operators, raw payloads or snapshot BLOBs to guess associations.
