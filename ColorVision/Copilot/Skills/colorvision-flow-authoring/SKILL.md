# ColorVision Flow authoring

Use ColorVision's structured Flow tools. Never parse or edit a `.stn` file as text.

## Workflow

1. Call `InspectFlowGraph` to obtain the active graph, stable instance and port ids, `revision`, and `sourceInstanceId`. Use an exact `node_id` for a focused read when appropriate. When complete graph topology is needed, finish the `section=nodes` stream, then start `section=edges` without a cursor while passing the returned revision and source instance as `expected_revision` and `expected_source_instance_id`; finish that edge stream too. Node pages contain only bounded internal edges, so finishing nodes does not establish complete connectivity. Follow each stream's `has_more` and `next_cursor` unchanged, keeping section, focus and include-properties options fixed; page limits may change. A stale binding requires a fresh read, not mixing pages. When initial structural diagnosis would help, call `ValidateFlowGraph` with the exact revision as `expected_revision` before proposing changes.
   Node overview ports and parameter text are also bounded, with totals and truncation indicators. Read complete port rows through `section=ports`, and parameter rows through `section=properties` with explicit `include_properties=true`; use `max_items` (1-200, default 80) and continue the chosen stream. Bind both expected identifiers on the first independent detail page when combining evidence. Finishing parameter rows does not recover values beyond the redaction and 512-character text limit.
2. For `add_node`, call `SearchFlowNodeCatalog` with a domain term such as `相机` or `camera`. Use the returned exact `typeKey`; never invent a .NET type name. If multiple types match, ask which behavior or device is intended when the choice changes the result.
3. For `set_property`, use the exact stable node id from the graph and writable `propertyName` from the catalog. Pass the value in the node descriptor's string form.
   Parameter display labels from graph overview or property rows are not writable property identifiers. Obtain the exact writable `propertyName` from `SearchFlowNodeCatalog`; a CLR `propertyName` in a detail row still requires the catalog's writable and descriptor checks. Use the properties stream when the overview omitted needed current parameter rows. Detail rows cover successfully captured simple visible summaries, and `parameterIndex` is only a zero-based position in that captured summary, not a persistent property identifier.
   Inspect `descriptorType`, `declaredEnumNames`, `isFlagsEnum`, and `booleanStringCandidates`. Use exact native enum names and the returned standard Boolean strings, not localized display labels. These declarations are not the complete business-valid domain: flags do not guarantee arbitrary combinations, and empty candidates do not mean read-only; check `isWritable` separately. Custom descriptors and unknown formats still require formal `PreviewFlowPatch` validation. Do not infer numeric bounds from descriptions or assume nullable input or null-clearing support.
   Sensitive CLR property names or display labels make the property unavailable for editing and the catalog reports `isWritable=false`. A harmless CLR name does not override a sensitive display label; do not try aliases to bypass that boundary.
4. For `connect` or `disconnect`, use exact stable source and target instance ids and the source `out:N` and target `in:N` port ids from the graph. Read the required connections from the edges stream, including links between different node pages. Do not infer ports from display order or names. A disconnect requires the Guid D instance ids and all four identifiers of one existing edge; a missing edge must fail, not become a successful no-op or whole-port disconnection.
   For rewiring, preview and obtain approval for the disconnect first, then inspect the graph again and separately preview and obtain approval for the connect using the new revision. These are two independent operations, not an atomic batch or a promise of cross-operation rollback.
5. Call `PreviewFlowPatch` with exactly one operation and the current revision. Describe the validated change, then call `ApplyFlowPatch` only when the request clearly asks for it; wait for explicit approval.
   Preview parameter values are redacted using both CLR names and display labels; string fields also redact inline credentials. Do not treat redacted output as the original configuration or try to recover hidden values. The host retains the source values for validation and fingerprints.
   For `set_property`, approval is shown only after a successful formal preview. Review the sanitized old value and the descriptor-converted new value in `ReviewDetails`. A sensitive display label causes rejection before any approval action is created; do not resubmit it through a harmless CLR alias.
   For `disconnect`, make the exact source/target nodes and ports being removed explicit in the review. If structural validation reports `valid=false` after disconnection, report that result without adding unrequested repairs, saving, or running the graph.
   When the user asks to inherit the current camera acquisition settings, choose a catalog type with `canInheritCameraDefaults`, set `inherit_camera_defaults=true` in the preview, and copy the returned node's exact `cameraDefaultsFingerprint` into `camera_defaults_fingerprint` on apply. Review the complete `cameraDefaults` with the user. Without this explicit option, new nodes retain their constructor defaults. A settings mismatch requires a new preview and approval.
6. Call `InspectFlowGraph` again. Verify that the revision changed and that the node, property, or edge now matches the request. Then call `ValidateFlowGraph` with the new exact revision as `expected_revision` and report `valid` and `diagnostic`. A successful check with `valid=false` is a completed structural result; do not expand the requested change or save or run the flow to fix it. A stale revision requires reading the graph again before checking.

## Safety boundary

- Do not add or edit nodes while the flow is running.
- Each patch performs exactly one `add_node`, `set_property`, `connect`, or `disconnect` operation. It never saves or runs the flow.
- Never change password, token, secret, authorization, bearer, license, or similar sensitive properties, whether identified by their CLR name or display label. Template patch candidates omit sensitive node parameters; their absence does not grant permission to discover or change them through another surface.
- Do not simulate node removal, whole-port disconnection, or batch graph edits with file or shell tools.
- Recovery within the disconnect transaction covers only the reviewed edge and editor history, not arbitrary changes or external side effects already made by callbacks. Do not describe rewiring as a complete business transaction.
- Treat a revision mismatch as a stale preview: inspect again and create a new preview.
- Use `colorvision-flow-diagnostics` instead when the request is diagnosis without an explicit graph change.
- Structural validation reuses the host's current save checks. It does not prove that every branch is complete, devices are ready, algorithm parameter semantics are correct, or execution will succeed.
